# 로컬 회의록

**음성·영상에서 논제 중심의 한글 회의록과 영상 요약을 만드는 로컬 웹 앱입니다.**

Ubuntu에서 실행하고 브라우저로 사용합니다. Windows에서는 WSL Ubuntu를 통해 실행할 수 있습니다. 음성 전사와 화자 구분은 PC에서 처리하며, 한글 요약 생성에는 별도 구독으로 로그인한 Codex CLI를 사용합니다.

[주요 기능](#주요-기능) · [설치 및 실행](#설치-및-실행) · [사용 방법](#사용-방법) · [데이터 및 운영](#데이터-및-운영) · [개발 및 문서](#개발-및-문서)

> 음성·영상·화자 임베딩은 로컬에 보관합니다. AI 요약에 필요한 텍스트와 메타데이터만 Codex로 전송합니다. 새 웹 입력은 AI 생성을 사용하며, 과거의 전사 전용 자료를 앱 업데이트만으로 전송하지 않습니다.

## 주요 기능

| 기능 | 설명 |
| --- | --- |
| 회의록 | 논제별 논의·결론·결정·할 일을 정리하고, 내용을 편집해 새 버전으로 저장할 수 있습니다. |
| 영상 요약 | 영상 파일이나 YouTube 링크에서 주요 주제를 정리합니다. 수치·주장·전망은 관련 주제 본문에 통합합니다. |
| 자동 음성 분석 | 언어와 화자를 자동 인식합니다. `large-v3-turbo` CPU INT8 전사, 한·영 정렬, pyannote 화자 구분을 사용합니다. |
| 음성 확인 | 주제의 시작 시각을 눌러 해당 구간을 재생할 수 있습니다. YouTube 원본 링크도 제공합니다. |
| 처리 관리 | 대기열·진행 상태·취소·재시도·중단 복구를 지원합니다. AI 재생성은 전체 음성 분석과 별도로 처리합니다. |
| 검색 및 내보내기 | 제목·본문을 검색하고, 결과를 Markdown 또는 텍스트로 다운로드할 수 있습니다. |
| 로컬 운영 | 자료 보관·삭제, 백업·복원, 진단, 선택적 systemd 사용자 서비스를 지원합니다. |

구현 및 검증 상태와 알려진 한계는 [마일스톤](docs/milestone.md)에서 확인하실 수 있습니다.

## 설치 및 실행

### 실행 환경

| 항목 | 지원 범위 및 준비 기준 |
| --- | --- |
| 운영체제 | Ubuntu 24.04 LTS x86_64를 지원합니다. Windows에서는 WSL Ubuntu를 사용합니다. |
| 하드웨어 | 준비 기준은 RAM 32GB, CPU 6코어 이상입니다. 처리 속도는 장비에 따라 달라집니다. |
| 설치 위치 | Linux 파일시스템을 사용합니다. `/mnt/c`·`/mnt/d` 설치는 지원하지 않습니다. |
| 입력 제한 | 파일당 최대 2GB(2,000,000,000바이트)·120분을 지원합니다. |
| 화자 인식 | 화자 수는 자동으로 인식하며, 상한은 12명입니다. |
| AI 요약 | 별도 런타임의 Codex 구독 로그인이 필요합니다. |

### 1. 환경과 모델을 준비합니다

저장소를 체크아웃하거나 번들을 풀고, 해당 디렉터리에서 일반 사용자로 실행하세요.

```bash
# 필요한 관리자 패키지 명령을 확인합니다.
bash scripts/install-ubuntu.sh --system-plan

# 안내된 시스템 패키지를 설치한 뒤 도구와 실행 환경을 준비합니다.
bash scripts/install-ubuntu.sh

# Hugging Face에 로그인합니다.
.venv/bin/hf auth login
```

모델을 준비하기 전에 소유자가 [pyannote 이용조건](https://huggingface.co/pyannote/speaker-diarization-community-1)을 확인하고 동의해야 합니다. 아래 옵션은 웹에서의 동의나 로그인을 대신하지 않습니다.

```bash
bash scripts/prepare-models.sh --accept-model-terms
bash scripts/login-codex.sh
bash scripts/doctor.sh
```

모델 리비전과 해시는 [`model_manifest.json`](src/meeting_minutes/model_manifest.json)에, 의존성과 모델 이용 고지는 [THIRD_PARTY](notices/THIRD_PARTY.md)에 있습니다.

### 2. 앱을 실행합니다

```bash
bash scripts/run.sh
```

브라우저에서 **[http://127.0.0.1:8765](http://127.0.0.1:8765)**를 여세요. 회의 목록·업로드·편집은 키 없이 사용할 수 있습니다. 설정·진단에 들어갈 때만 `~/.config/local-meeting-minutes/owner-key`로 로그인합니다. 로그아웃해도 일반 작업은 계속 사용할 수 있습니다.

Windows PowerShell에서 실행하려면 `-Repo`를 실제 Linux 저장소 경로로 바꾸어 사용하세요.

```powershell
powershell -File scripts/dev-windows.ps1 -Distro Ubuntu -Repo "/home/<사용자>/src/local-meeting-minutes"
```

키와 토큰은 채팅이나 Git에 넣지 마세요.

## 사용 방법

### 회의록을 만듭니다

1. **새 회의**에서 파일·제목·회의 일시를 입력합니다. 일시는 현재 한국 시간으로 표시되며, 언어와 화자 수는 자동으로 인식합니다.
2. 업로드하고 처리를 시작합니다. 제목을 비우면 AI 요약 시 제목을 생성합니다.
3. 상세 화면에서 요약과 논제를 읽고, 시작 시각을 눌러 근거 음성을 확인합니다.
4. **회의록 편집**에서 논제·결정·담당자 등을 보완하고 **수정본 저장**으로 새 버전을 만듭니다.

최초 결과는 `초안`, 수정 이후에는 `버전02_0927`처럼 버전 번호와 저장일(KST)을 함께 표시합니다. 재논의 시각은 다른 논제를 거쳐 이전 논제로 돌아온 경우에만 구분합니다. 별도의 최종 확정 버튼은 제공하지 않습니다.

### 영상을 요약합니다

**영상 요약**에서 **새 영상 요약**으로 파일을 올리거나, **YouTube 영상 요약**으로 사용할 권한이 있는 단일 영상 링크를 등록합니다. 제목을 비운 YouTube 입력은 원본 영상 제목을 사용합니다.

요약본은 편집 없이 읽고 내보낼 수 있으며, 화면에는 최신 결과만 표시합니다. 음성 재생기는 핵심 요약 위에 있고, 원본 영상 링크는 전체 요약에 하나만 표시합니다. 로컬 음성이 만료되어도 원본 링크는 유지됩니다.

수치·단위·기간과 발언 주체는 주요 주제 본문에 포함하도록 생성합니다. 과거 저장본은 자동으로 바꾸지 않으며, 새 구성으로 정리하려면 **요약 재생성**을 사용하세요.

<details>
<summary>YouTube 지원 범위를 확인합니다</summary>

- 공개·일부 공개로 제공되는, 실시간 방송 중이 아닌 단일 영상 전체를 지원합니다.
- 로그인·쿠키가 필요한 자료, 실시간 영상, 재생목록 자체, DRM 및 직접 HTTPS 음성 형식이 없는 영상은 지원하지 않습니다.
- 길이·크기 제한은 파일 입력과 같습니다. 링크로 가져오지 못하면 사용할 권한이 있는 파일을 직접 올릴 수 있습니다.
- 설치기는 고정된 yt-dlp·EJS·Deno와 bubblewrap을 준비합니다. 진단에서 격리 실행 가능 여부를 확인할 수 있습니다.
- 다운로드는 인증 파일을 노출하지 않는 격리 환경과 제한된 HTTPS 전송 경로를 사용합니다.

</details>

### 처리와 재생성을 관리합니다

새 회의·영상의 전체 분석은 하나의 대기열에서 순서대로 처리합니다. **초안 재생성**과 **요약 재생성**은 음성을 다시 분석하지 않고, 저장된 전사로 AI 요약만 수행합니다. 재생성 대기열은 전체 분석과 별도로 한 건씩 실행됩니다.

회의록의 재생성 결과는 새 기본 버전이 되며, 이전 수정본은 보존됩니다. 생성 도중 별도로 저장한 수정본이나 새 전사는 덮어쓰지 않습니다. 편집 중이 아니면 완료된 최신 결과를 자동으로 표시합니다. 영상 요약도 내부 저장 이력을 보존하지만 버전 선택 UI는 제공하지 않습니다.

업로드 응답을 받지 못해 새로고침했다면 같은 파일을 다시 선택해 이어갈 수 있습니다. 앞 작업이 차단되면 재시도·전사만 종료·취소로 해소하세요. 취소·재생성·자료 삭제 등의 확인은 사이트 모달로 안내하며, 취소 또는 Escape로 중단할 수 있습니다. 탭 닫기·새로고침 시 미저장 변경은 브라우저 기본 경고로 보호합니다.

### 결과를 내보냅니다

상세 화면의 AI 생성 박스에서 **텍스트 내보내기** 또는 **Markdown 내보내기**를 선택하세요.

| 구분 | 내보내는 결과 | 파일명 예시 |
| --- | --- | --- |
| 회의록 | 현재 선택한 버전을 내보냅니다. | `minutes_ver02_0927.md` |
| 영상 요약 | 화면에 표시된 요약을 내보냅니다. | `summary_ver03_0927.txt` |

파일명에는 결과의 버전 번호와 저장일(KST)을 포함합니다. 두 형식 모두 Windows 사용자를 위해 **UTF-8·CRLF**로 제공합니다.

웹에서는 재생 시작 시각을 표시하지만, 다운로드한 결과에서는 제외합니다. 본문에서 의미 있는 날짜·시간·수치는 유지합니다. 읽기 화면과 내보내기에서는 마침표로 끝나는 문장을 줄바꿈하며, 소수점·URL·일반적인 영문 약어와 기존 문단을 보존합니다. 저장 원문·편집 입력·제목은 변경하지 않습니다.

## 데이터 및 운영

### 자료 보관

| 자료 | 기본 보관 기간 |
| --- | --- |
| 원본 및 재생용 음성·영상 | 7일 동안 보관합니다. |
| 전사·정렬·화자 임베딩 | 30일 동안 보관합니다. |
| 회의록·영상 요약 및 저장 버전 | 영구 보존합니다. |

보관 기간은 입력 수신 완료일부터 계산하고, 처리 중인 자료는 작업 종료 후 정리합니다. 기존 사용자 정책은 유지하며, 기존 자료에는 이전 시점의 일회성 유예를 적용합니다.

원문이 만료되어도 회의록 편집·저장과 결과 열람·내보내기는 가능합니다. 음성 재생·원문 확인·원문 기반 재생성은 필요한 자료가 남아 있을 때만 가능합니다.

### 백업과 복원

백업 전에 앱을 정지하세요. 백업에는 회의 내용이 포함되지만 인증·로그인 세션은 포함되지 않습니다. 복원은 파일 크기와 해시를 검사한 뒤, 존재하지 않는 새 경로에만 수행합니다.

```bash
bash scripts/stop.sh
bash scripts/backup.sh /absolute/new-backup.tar.gz
bash scripts/restore.sh /absolute/new-backup.tar.gz /absolute/new-data-directory
MINUTES_DATA_DIR=/absolute/new-data-directory bash scripts/run.sh
```

별도로 만든 백업은 앱을 삭제해도 자동으로 지워지지 않습니다.

### 경로와 서비스

데이터·설정·캐시의 기본 경로는 HOME/XDG 규칙을 따릅니다. `MINUTES_DATA_DIR`, `MINUTES_CONFIG_DIR`, `MINUTES_CACHE_DIR`로 변경할 수 있습니다. 기본 Codex 구독 인증 경로는 `~/.local/share/local-meeting-minutes/codex-home`입니다. 다른 장비나 사용자 환경에서는 인증을 복사하지 말고 다시 로그인하세요.

선택적으로 systemd 사용자 서비스 파일을 생성할 수 있습니다. 활성화 방법은 명령 실행 후 출력되는 안내를 따라 주세요.

```bash
bash scripts/install-service.sh
```

실제 사용 서버는 작업 처리기를 활성화해야 대기열이 실행됩니다. `MINUTES_WORKER_ENABLED=false`는 격리된 화면 시험에서만 사용하세요.

### 개발 중: AI 공급자 선택 (M3)

Gemini API·Codex CLI·Claude CLI의 공통 생성 경로와 소유자 설정 화면을 구현했습니다. 아직 최종 인수 전이며, 실행 중인 기존 앱에 자동 적용되지는 않습니다.

설정 로그인 후 **AI 연결 및 선택 → 자료 보관 → 진단** 순서로 확인하실 수 있습니다. Gemini는 새 API 키를 저장하고 **연결 확인**을 실행한 뒤 활성 AI로 선택합니다. CLI는 전용 런타임 로그인 후 연결을 확인합니다. 준비되지 않은 항목은 선택할 수 없으며 확인 상태가 만료되면 다시 검사합니다. 다른 탭과 충돌하면 **상태 새로고침** 후 다시 선택해 주세요.

Gemini 키는 설정 디렉터리의 `.apikey/gemini.json` 한 파일에 제한된 권한으로 보관합니다. 저장·화면 이탈·로그아웃·세션 만료 시 입력란을 비우며, 기존 키 보기·복사 기능은 없습니다. 같은 OS 사용자나 root를 막는 암호화는 아닙니다. 인증 파일은 Git·소스 동기화·릴리즈·백업에서 제외하며 앱의 키 삭제는 Google의 키 폐기를 대신하지 않습니다. Gemini의 요금·데이터 처리 조건을 확인하고 무료 서비스에는 기밀·민감정보를 보내지 마세요.

AI 선택은 새 업로드 완료·YouTube 등록·초안 재생성 시점부터 적용됩니다. 기존 대기 작업과 재시도는 등록 당시 공급자·모델·문맥/출력 한도·소비 예산을 유지합니다. 등록할 때 모델 한도 정보가 없었다면 로컬 처리는 진행하지만 AI 생성은 차단되며, 연결 준비 후 새 생성이 필요합니다. 현재 AI로 바꾸려면 기존 작업을 전사만 완료하거나 취소한 뒤 저장된 전사에서 새 생성을 요청하세요. 준비된 AI가 없어도 기존 결과 열람·편집·내보내기와 로컬 음성 처리는 가능합니다.

Claude는 `python3 scripts/setup-claude.py`로 설치 계획을 확인한 뒤 `--install`로 고정 2.1.283 런타임을 선택 설치합니다. 구독 로그인은 `.venv/bin/python scripts/login-claude.py`를 로컬 터미널에서 실행합니다. 별도 런타임 HOME을 사용하며 API 키 과금 인증은 허용하지 않습니다. 현재 개발 인수에서는 계정 연결을 보류하여 실제 Claude 생성은 미검증입니다.

Gemini는 `gemini-3.8-flash`의 JSON 모드로 생성하고 앱에서 문서 스키마·근거를 검증합니다. 짧은 가상 전사의 회의록 실제 생성은 통과했으며 영상 요약은 Google HTTP 503으로 실패해 실제 인수는 남아 있습니다. Codex의 회의록·영상 요약 실제 생성은 통과했습니다. Claude 계정 연결은 보류 상태입니다.

`bash scripts/doctor.sh`는 로컬 처리 필수 환경과 선택적 AI 준비 상태를 구분합니다. Gemini·Claude가 미연결이어도 로컬 필수 검사를 통과할 수 있으며, 이는 외부 생성 성공을 뜻하지 않습니다. 키 파일 존재만 확인하며 인증·모델 접근은 소유자 설정의 연결 확인에서 검사합니다. 사용자 서비스는 지정한 config 경로와 Codex·Claude 전용 런타임 경로를 유지합니다.

AI 예산은 공급자별로 따로 집계·설정합니다. Codex·Claude 기본 한도는 각각 2,000만 토큰이며 입력과 출력을 합산합니다. Gemini는 주간 토큰 제한 대신 **하루 10회·분당 최대 2회**의 요청 한도를 사용합니다. 소유자 설정의 **AI 사용 예산**에서 사용량·예약량·갱신 시각을 확인하고 한도를 변경할 수 있습니다. Codex·Claude는 한국 시간 월요일 0시, Gemini는 미국 태평양 시간 자정에 갱신됩니다. 완료된 Codex·Claude 결과는 출력 토큰이 문맥 예약량을 넘었다는 이유로 버리지 않습니다. Codex·Claude는 진행 중 호출 하나의 초과를 허용하고, 소진 후에는 다음 AI 호출을 대기시킵니다. 한도 인상이나 주간 갱신 후 FIFO 순서로 자동 재개하며, 대기 중 원문은 자동 보관 삭제에서 보호됩니다. 취소·직접 삭제는 가능합니다.

주간 예산은 계정 전체 구독 한도가 아닌 이 앱의 사용 기록입니다. 캐시 입력은 공급자별 usage 의미에 맞춰 중복 없이 집계합니다. 사용량 미확정 호출은 입력 한도와 출력 예약량을 합한 추정 예약을 유지하므로 실제 청구량과 다를 수 있습니다. 주를 걸친 호출은 시작한 주에 집계하고, 회의를 삭제해도 내용·인증을 담지 않은 예산 기록은 유지됩니다. 업그레이드 시 남아 있는 과거 사용 기록도 이전하며 이미 삭제된 기록은 복구할 수 없습니다. 시간·파일 크기·작업별 호출 횟수 제한은 유지합니다.

M3 범위 검수와 실제 공급자 인수는 아직 완료되지 않았습니다. Claude 계정 연결은 보류 상태입니다. 자세한 진행은 [마일스톤](docs/milestone.md)을 참고해 주세요.


Gemini 실패 진단은 HTTP 상태·서버 상태 분류·연결/읽기 시간 초과·숫자 재시도 대기 시간만 보존하며 키·전사·응답 원문은 기록하지 않습니다. 서버 503은 `AI_SERVICE_UNAVAILABLE`, 그 외 서버 5xx는 `AI_SERVER_ERROR`로 연결 오류와 구분합니다. 생성 실패 진단은 호출 사용 기록에 남고 명시적 연결 검사는 해당 응답에 포함합니다. 연결 상태 캐시는 간략 코드만 유지합니다. Gemini 429는 자동 반복 호출하지 않으며, 일시적 서버 오류는 기존 최대 2회 재시도 범위에서 제공된 대기 시간을 따릅니다. 30초를 넘는 대기가 요구되면 자동 재시도하지 않습니다.


Gemini 기본 요청 한도는 [3.6 Flash 무료 계정 직접 측정 자료](https://aiplug.work/en/blog/gemini-free-tier-limits)의 20회/일·5회/분을 절반 수준으로 낮춘 추정값입니다. [공식 한도](https://ai.google.dev/gemini-api/docs/rate-limits)는 프로젝트마다 다르며, 3.8 또는 현재 계정의 무료량을 보장하지 않습니다. 설정에서 일일·분당 한도를 각각 조정할 수 있습니다. 실패·재시도·분할 생성도 매 요청 1회로 계산하며, 한도 소진 작업은 갱신/인상 후 자동 재개됩니다. TPM과 다른 앱의 같은 프로젝트 사용량은 이 앱이 제어하지 않습니다. 기존 Gemini 토큰 기록은 보존하며, 이전 중 시각이 없는 최근 호출은 안전하게 이전 당일 사용으로 계산합니다.

Claude 기본 모델은 `claude-opus-5-5`이며 생성 시 `--effort high`를 명시합니다. 기존 Sonnet 기본 선택은 DB 0017에서 Opus로 이전하고, 등록된 작업의 모델과 다른 사용자 지정 모델은 보존합니다. 계정 연결 보류 상태는 유지하며 실제 생성 검증은 하지 않았습니다.

설정의 실행 환경 진단은 Codex·Claude 각각 실행 파일, 별도 인증 위치, CLI 버전, 로컬 로그인 상태를 표시합니다. 모델 선택과 중복되는 Codex 모델 항목은 표시하지 않습니다. 로컬 진단은 최대 30초 재사용하며 인증 원문이나 계정 식별 정보를 반환하지 않고 외부 생성은 실행하지 않습니다.
