## 현재 상태

MVP G1~G6 구현과 R1/R2/R3 검증을 완료했다. 후속 **M2: 웹 사용성·논제 중심 회의록·영상 요약**을 아래에 등록했다. **M2 W0~W6 구현과 범위 검수, 실제 YouTube 획득·시간 매핑 및 설치 인수를 완료했다.** 기존 완료 기록과 후속 화면·재생성 개선을 보존한다. 다음 작업은 문서 마지막의 **M3: AI 공급자 선택·Gemini 키 보관·전역 생성 경로 통합**이다. **M3는 PLANNED이며 아직 구현·실행 검증한 기능이 아니다.**

이 문서는 Git만 받은 사람을 위한 구현 요약과 활성 작업 계획이다. 사용법은 [README](../README.md), 작업·검수 규칙은 [workflow](workflow.md)에 있다. 개인 환경의 `.workflow`는 Git에 포함되지 않으므로 없다고 해서 구현이 누락된 것은 아니며, 과거 실행 증거를 새 환경의 통과 결과로 간주해서도 안 된다.

## 현재 구현의 구조와 계약

아래는 M3 적용 전 현재 코드의 동작 계약이다. 위 G1~G6 표와 완료된 M2 기록은 보존한다. M3는 기존 Codex 전용 생성 경계를 확장하며, 명시적으로 바꾸지 않은 후속 개선과 안전성 계약은 유지한다.

- `src/meeting_minutes`가 백엔드·모델·작업 관리자, `apps/web`이 웹 UI, `tests`가 계약/통합 검사, `scripts`가 설치·운영·검증 도구다. 고정 의존성은 `uv.lock`, `apps/web/package-lock.json`, 모델 리비전은 `model_manifest.json`에 있다.
- API는 무거운 모델을 로드하지 않는다. 데이터 디렉터리별 단일 관리자가 작업별 자식을 실행한다. SQLite 원자적 claim과 OS 잠금으로 분석과 AI 재생성 각각 활성 작업을 하나로 제한한다. 두 종류는 독립적으로 실행한다.
- 입력은 최대 2,000,000,000바이트·7,200초다. 새 웹 입력의 언어·화자 수는 자동이며 화자 상한은 12명이다. 과거 수동 설정은 기록으로 보존한다. 여러 오디오 트랙은 명시적으로 선택하고 영상은 음성만 사용한다.
- `large-v3-turbo` CPU INT8와 pyannote community-1을 사용한다. 전체 회의 시간축과 화자 ID를 유지하고 정렬 실패는 원문 구간 시각으로 대체한다. 병합 후보는 자동 확정하지 않는다.
- FIFO의 차단된 앞 작업을 몰래 건너뛰지 않는다. 취소는 자식 종료 확인 후 확정한다. PID뿐 아니라 부팅 ID·시작 tick을 확인해 다른 프로세스를 보호한다.
- 완료 산출물은 입력·설정·모델 지문과 파일 해시가 맞아야 재사용한다. 저장 직전 시도 ID·취소·삭제를 확인해 늦은 결과를 차단한다.
- 원본 전사와 확정 회의록은 덮어쓰지 않는다. 수정은 새 버전이며 낙관적 충돌 검사를 한다. 회의록은 시작 시점 전사 snapshot과 실제 근거 ID를 참조한다.
- 새 입력은 연결된 AI 생성을 요청한 상태를 저장하며, 과거 전사 전용 자료를 읽기만 해서 외부 전송하지 않는다. Codex는 별도 런타임 인증·작업 디렉터리에서 텍스트만 처리하고 개발 지침·도구를 상속하지 않는다. 호출 예약은 재시작해도 유지한다.
- 일반 로컬 세션과 소유자 세션을 분리한다. 목록·입력·편집은 키 없이 사용하며 설정·진단 API만 소유자 권한을 추가 요구한다. 로그아웃 후 일반 작업은 유지한다.
- 회의록은 논제 중심으로 읽고 편집·저장한다. 영상 요약은 별도 목록·스키마·읽기 전용 뷰를 쓰며 파일과 YouTube 입력 모두 같은 FIFO와 전사 경로를 사용한다. 전사문 열람·교정 UI는 제공하지 않는다. 기존 전사 데이터와 버전 API는 유지한다.
- 기본 자동 보관은 미디어 7일·전사/정렬/임베딩 30일·결과 영구 보존이다. 원문 만료 후에도 회의록 편집·확정과 결과 내보내기가 가능하다. 영상 전체의 원본 링크도 유지한다.
- 로그에 원문·인증·임베딩을 남기지 않는다. 삭제는 작업 종료 후 자료를 정리한다. 백업은 인증을 제외하며 복원은 manifest 크기·해시 검사 후 새 경로에만 공개한다.
- 외부 발행은 구현하지 않았다. `minutes.generated`는 검증된 초안 저장, `minutes.approved`는 특정 버전의 사용자 확정이라는 의미 계약만 있다.

## 검증 기준점과 알려진 한계

MVP 최종 문서 체크포인트는 `a3cf51ed5e4e486337122388a9afd148c2a0cac2`, R3 수정 검증 코드는 `ebd08935e1ab20530b6ae07ebeee726027c89457`이다. 이후 변경은 별도 범위 검증으로 관리한다. R1의 동시 트랙 선택, R2의 날짜 표현 근거, R3의 취소 테스트 모델 격리·최종 번들 설치 증거 문제는 모두 수정 확인됐다. 전체 Python 회귀의 통과 77개와 TypeScript·E2E 4개를 보존하고 R3 재검증 4개로 수정 범위를 확인했다.

Ryzen 5800X·WSL 24GiB/8vCPU·앱 4스레드에서 약 3분 한국어/영어 입력은 각각 224.4초/214.0초였다. 과거 120분 반복 음성 시험은 7,497.9초, 관측 최대 RSS 약 3.85GiB, 스왑 0으로 완료했다. **이 기록은 참고용이며 향후 마일스톤·전체 검증의 필수 조건이 아니다. 120분 시험은 사용자 지시 때만 별도로 수행한다.**

자연 12인 회의 정확도·CER/WER/DER는 평가하지 않았다. 혼용·겹친 발화·근거 의미는 사용자 검토가 필요하다. GPU, 실시간 STT, 다중 사용자, 자동 공급자/API 키 폴백, 외부 서비스 발행은 범위 밖이다. Gemini API와 Claude CLI의 명시적 선택 지원은 아래 M3의 신규 구현 범위다.

## 완료 마일스톤 M2 — 웹 사용성·논제 중심 회의록·영상 요약

상태: **DONE / 구현·범위 검수·실제 실행 증거 인수 완료**. 목표는 근거 조각을 수작업으로 조립하는 화면이 아니라, **자동으로 정리된 주요 논제를 읽고 필요한 시작 구간만 들은 뒤 내용을 수정하는 웹**이다. 영상은 같은 전사 기반을 재사용하되 편집 없는 별도 요약본으로 제공한다.

현재 인수인계 요점:

- **W1~W3:** 발언 파생 전사, schema 2 논제/시작 위치, 과거 결과 호환, 원문 만료 후 편집·확정·내보내기와 7/30/영구 보관을 구현했다. M2-A에서 지적된 terminal 작업의 만료 차단은 수정·재검수 통과했다. 자동 화자 배정은 유지하며 근거 없는 병합 보정은 추가하지 않았다.
- **W4~W5:** 키 없는 일반 사용, 설정·진단 보호, 자동 인식/KST/재시도 복구, 읽기 전용 영상 요약과 격리된 YouTube 획득 경로를 구현했다. 최근 200개 밖의 대기 작업도 조회하고 부분 음성을 전체 성공으로 저장하지 않는다. M2-B의 마이그레이션·문구 assertion·공유 venv 격리 경로 지적은 수정했다. 전체 Python 1회에서 통과한 범위와 실패 항목 재검증을 결합했고, 브라우저 13개는 기존 10개 통과와 수정한 3개 재통과로 확인했다. 마지막 격리 경계 5개도 기존 검증 세션에서 통과했다.
- **실제 생성:** 교정된 하나의 가상 전사를 기준으로 이전/현재 회의록·영상 요약을 실제 Codex 5회 호출 안에서 비교했다. 초기 schema title 누락 실패와 수정 후 성공을 모두 보존했다. 논제·번복·농담/미결·수치/시작 위치를 확인한 제한된 결과이며 일반적인 정확도 향상을 의미하지 않는다.
- **설치·실행:** `238ccab` 후보의 번들을 별도 HOME·한글/공백 경로에 무패치 설치하고 파일 해시·웹/로컬 세션·진단 권한을 확인했다. 인증·모델은 복사하지 않았다. 120분 시험은 실행하지 않았다.
- **최종 인수:** 허가된 Coffee Run 전체 음성 184.661초·약 2.9MB를 실제 획득했고, 분석용 WAV와 길이 차이는 21ms였다. 직접 연결 설정과 다운로더 출력 격리 오류를 수정했으며, M2-B-005의 범위 검사 17개·현재 증거 검사·수정 커밋의 새 설치본이 통과했다. 최초 두 실패와 이후 성공을 모두 보존한다. 이 획득 시험은 음성 인식·요약 품질 평가와 구분한다. 현재 활성 미완료 항목은 없으며 상세 증거는 `.workflow`에 있다.

```text
/goal AGENTS.md와 docs/workflow.md를 먼저 읽고 docs/milestone.md의 활성 마일스톤 M2를 W0~W6 및 인수 조건에 따라 구현하라. 기존 MVP와 사용자 자료를 보존하면서 논제 중심 회의록 편집, 문장 단위 전사와 논제 시작 위치, 7일/30일/영구 보관, 설정·진단만 소유자 인증, 자동 인식 업로드, 읽기 전용 영상 요약과 YouTube 링크 입력을 완성하라. 실제 LLM은 기존 Codex CLI만 사용한다. 개발·시험은 Ubuntu/WSL에서 수행하고 Windows 작업 사본을 동기화한다. 기존 Astra medium 마스터와 Sol 5.6 high 검증자 두 세션만 사용하며 검증은 workflow의 codex queue 절차로 커밋과 범위를 고정해 위임하라. 매 작업의 전체 검증, 무제한 모델·CLI·네트워크 재실행, 명시적 사용자 지시 없는 120분 soak를 하지 마라. 완료한 검증 증거는 유효한 범위에서 재사용하고 실제 실행과 mock을 구분하라. 기존 상태·예산·검수 결과를 보존하고 차단 시 독립 작업을 진행한 뒤 정확한 재개 지점을 남겨라. 구현과 인수 검사를 대조하고 README·milestone·필요한 workflow를 동기화한 뒤 실제 완료 항목과 미완료·외부 차단을 보고하라. 기능이나 검사를 누락시키고 완료로 처리하지 마라. 이 goal은 새 원격 push·공개 배포나 별도 유료 서비스 사용 승인을 포함하지 않는다.
```

### M2.1 범위와 우선 결정

- 기존 React/FastAPI/SQLite/로컬 파일/단일 워커를 유지한다. 개발·검증은 Ubuntu/WSL, 배포 대상은 Ubuntu 24.04 LTS x86_64다. Windows 네이티브 ML 지원을 추가하지 않는다.
- 실제 생성기는 개인 구독 **Codex CLI 하나**다. 사용자 문구와 작업 종류만 공급자 중립적으로 만들고 Gemini·다른 API·로컬 LLM·소셜 로그인·외부 발행은 구현하지 않는다. 미래 공급자 확장을 이유로 거대한 플러그인 체계를 만들지 않는다.
- 화자 수 상한 12명, 입력 120분·2,000,000,000바이트, CPU INT8·pyannote community-1, 전체 원본 시간축, 분석·AI 재생성 각각 하나씩 FIFO, 취소·재시도·복구는 유지한다. 최대 지원 길이는 장시간 시험의 실행 승인이 아니다.
- 화면에서 사용자가 직접 화자 실명 식별·이름 변경·배정 변경·병합을 하는 흐름은 제거한다. 회의 내 자동 구분의 일관성을 목표로 하며 회의 간 인물 식별·생체정보 사전 등록은 하지 않는다.
- 새 웹 입력은 언어·화자 수 자동, 연결된 AI를 통한 결과 생성 항상 활성이다. 과거의 전사 전용 자료를 업데이트만으로 외부 전송하거나 유료 폴백하지 않는다.
- 회의록은 읽기 중심으로 보여주고 필요할 때 논제와 본문을 편집한다. 영상 요약은 읽기 전용이다. 두 종류는 목록·생성 스키마·프롬프트를 구분하되 대기열·저장·음성 처리 코드를 복제하지 않는다.

### M2.3 문장 단위 전사와 자동 화자 일관성

**원본 전사/정렬 → 읽기용 발언 단위 → 논제와 시작 위치**의 세 계층을 둔다.

1. 기존 단어 ID·시각·원문 snapshot은 불변으로 보존한다. 파생 `utterance`에는 ID, `start_ms`, `end_ms`, 읽을 수 있는 `text`, 자동 화자 ID, 구성 원본 ID, 불확실성 정보를 둔다. 파생 규칙 버전과 입력 전사 버전을 기록한다.
2. 원본 ASR의 문장·공백·구두점, 실제 화자 전환, 침묵·겹침과 적절한 길이 경계를 함께 사용해 발언을 묶는다. 한국어·영어의 공백을 망가뜨리거나 발언을 누락·중복시키지 않는다. 단순 고정 단어 수로 문장을 자르지 않는다.
3. 단어가 짧다는 이유만으로 발언 전체를 짧은 화자 샘플로 판단하지 않는다. 단어별 `150ms` 판정과 발언 수준의 신뢰 판단을 구분한다. 혼용·정렬 실패는 기존 원문 구간 시각으로 대체한다.
4. 전체 회의 기준 pyannote 구분을 유지하고 표시 번호는 회의 안에서 안정적으로 부여한다. 짧은 맞장구·화자 경계 흔들림은 충분한 주변 근거가 있을 때만 보정한다. 겹친 두 화자를 병합하거나 이름·발언 뜻으로 같은 사람을 추정하지 않는다. 불확실하면 미확정 상태를 유지한다.
5. 기존 임베딩·regular/exclusive 결과로 오분리 사례를 먼저 확인한다. 임의 유사도 기준으로 화자를 무조건 합치거나 별도 Whisper 세그먼트 임베딩 엔진을 다시 만들지 않는다. 자동 보정은 고정 평가 세트에서 원본 대비 개선·비회귀를 확인한 것만 기본 적용한다. 성능 개선이 확인되지 않으면 원본 방식을 유지하고 한계를 기록한다.
6. 화자 수정·병합 UI와 정상 사용자 흐름의 화자 변경 명령은 없앤다. 기존 사용자 수정 버전·화자 이름은 과거 자료 열람을 위해 보존하며 자동 재처리로 덮어쓰지 않는다. 전사문 열람·교정 UI는 후속 화면 정리에서 제거했으며 기존 버전 API와 데이터는 보존한다.
7. 이미 저장된 단어 전사는 모델 재실행 없이 파생 읽기 뷰를 만들 수 있게 한다. 단, 존재하지 않는 텍스트·시각을 보충하지 않는다. 파생 규칙 변경 시 관련 캐시만 무효화하고 STT·pyannote를 불필요하게 다시 실행하지 않는다.

### M2.4 논제 중심 회의록 생성·수정

#### 결과와 화면

기본 상세 화면 순서는 **회의 개요·요약 → 주요 논제 → 사용자가 보완할 결정·할 일**이다. 기본 상태에서는 읽기 좋은 문서로 보여주고 편집을 선택했을 때 입력란을 연다.

- 논제에는 제목, 논의 요약, 합의·제안·보류 등 현재 결론의 요지와 관련 시작 위치 1~n개를 담는다. 같은 논제가 뒤에 재등장하면 하나의 논제로 묶되 다른 논제를 거쳐 돌아온 경우에만 별도 시작 위치를 보존한다.
- 시간 버튼은 `03:12 논의 시작`, `18:40 재논의`처럼 표시한다. 내부 근거 ID 목록이나 단어 버튼을 기본 화면에 나열하지 않는다. 필요 시 보여주는 발췌도 문장과 주변 맥락이어야 한다.
- 시작 위치는 모델이 임의 숫자로 만들지 않는다. 모델은 유효한 발언 ID·구간을 선택하고 서버가 원본 시각으로 변환·정렬·중복 제거한다. 연속된 동일 구간은 합치고 논제와 무관한 앞선 발언을 시작점으로 잡지 않는다.
- 논제 위치를 누르면 같은 화면의 재생기로 이동해 해당 위치부터 들을 수 있게 한다. 편집 중인 입력·스크롤·선택 상태를 불필요하게 초기화하지 않는다. 1시간 이상은 `HH:MM:SS` 형식을 지원한다.
- 논제 제목·내용의 수정, 추가·삭제·순서 변경, 전체 요약 수정, 결정·할 일 직접 입력, 변경 취소·저장과 새 버전을 제공한다. 최종 확정 UI는 제공하지 않으며 과거 확정 버전과 호환 API는 보존한다. 저장하지 않은 변경 경고와 낙관적 충돌 검사는 유지한다. 재생성은 새 기본 버전으로 연결하며 수동 입력·과거 확정본의 저장 내용을 덮어쓰지 않는다. 생성 중 별도 편집이 있으면 해당 편집본을 기본으로 유지한다.
- 개별 근거를 모두 확인하거나 항목마다 `verified`로 바꾸는 것을 저장·문서 확정의 선행 조건으로 삼지 않는다. 사이트에서는 최종 검수·확정을 수행하지 않는다.
- 상세 결정, 담당자, 기한은 사용자가 보완하기 쉽게 둔다. 담당자는 화자 드롭다운에 종속시키지 않고 직접 입력할 수 있게 한다. 수동 항목은 자동으로 `user_authored` 등 출처를 구분하고 근거 없는 사용자 입력을 거부하지 않는다. 이를 위해 사용자가 먼저 검토 상태를 수동 전환할 필요가 없어야 한다.
- 안내는 결정·할 일 편집 영역에 짧게 한 번만 둔다: `자동 정리된 내용입니다. 구체적인 결정·담당자·기한은 직접 확인하고 보완하세요.` 업로드 화면에 삭제 요청한 안내 문구를 다시 추가하지 않는다.

#### 논제·결정·미결의 판단 규칙

- 전체 흐름에서 실제 주요 안건을 추출한다. 단순 질문 모음이나 모든 발언의 압축본을 만들지 않는다. 안건과 무관한 잡담·농담·수사적 질문·이미 해결된 질문은 미결로 남기지 않는다.
- 예: 농담으로 나온 `그럼 우리 다 퇴사할까요?`는 미결 질문이 아니다. `보안 검토가 끝나지 않아 다음 회의에서 배포 여부를 정하자`는 실제 후속 확인 사항이다. 질문부호나 특정 단어만으로 판정하지 않고 전후 맥락·응답·후속 합의를 함께 본다.
- 명시적 합의와 제안·추측·보류를 구분한다. 회의 후반의 번복·취소를 반영하고, 불확실한 농담을 실행 항목이나 확정 결정으로 승격하지 않는다. 근거가 부족한 미결 목록은 비어 있어도 된다.
- 자동 생성은 주요 논의와 결정 요지에 집중한다. 발언에 없는 실행 세부사항·담당자·날짜를 만들지 않는다. 명시된 내용도 자동 정리 초안이라는 출처를 유지한다.
- 긴 입력은 기존 문맥·호출 예산 안에서 발언·논제 경계를 고려해 분할한다. 청크 경계의 문맥과 뒤늦은 해결·번복을 통합하고 짧은 요약을 반복 재요약하며 맥락을 잃지 않는다. LLM 호출 단계 수를 늘리는 방식부터 택하지 않는다.
- 프롬프트 버전, 결과 스키마, 문서 종류, 파생 전사 규칙을 생성 식별자·캐시 지문에 반영한다. 기존 분할·통합·로컬 검증·schema 출력 모두 함께 수정한다. 프롬프트만 바꾸거나 JSON 형식 통과를 의미 정확도 통과로 간주하지 않는다.

#### 결과 계약과 과거 버전

결과는 버전 있는 구조화 JSON을 정본으로 둔다. 회의록의 `topics`에 논제별 시작 위치를 저장하고, 결과 자체에 제목·시각·문서 종류·생성 정보 등 열람에 필요한 최소 정보를 갖춘다. 원본 ID는 내부 추적용으로 남기되 UI의 필수 편집 단위로 쓰지 않는다.

기존 schema 1과 사용자 편집본은 읽기 호환을 제공한다. 필요한 변환은 새 버전 또는 읽기 어댑터로 하며, 모든 과거 회의의 LLM 재생성을 마이그레이션에 넣지 않는다. 전사가 남아 있는 이전 결과는 기존 근거를 읽을 수 있는 문장·시작 위치로 연결한다. 전사가 없어 복원할 수 없는 위치는 확인 불가로 남긴다.

### M2.5 자료 보관 기본값과 만료 후 동작

| 보관 대상 | 새 기본값 | 정책 |
|---|---|---|

- 통합 `media_days`, `transcript_days`, `enabled` 계약과 DB 마이그레이션을 마련한다. 결과 문서에는 자동 삭제 일수를 적용하지 않는다. 백엔드 기본값·DB 초기값·설정 폼·문구·시험을 일치시킨다.
- 신규 자료의 보관 기산점은 실제 입력 수신 완료 시각으로 고정한다. 회의가 열린 과거 날짜나 YouTube 게시일을 사용하지 않는다. 원본과 추출 음성은 같은 만료일을 쓰며 조회·수정·재생성·재시도로 수명이 계속 연장되지 않는다. 처리 중인 자료는 실행 상태·잠금 확인 후 종료될 때 정리한다.
- 기존 설치의 변경하지 않은 초기 정책은 7/30/영구·자동 삭제 켜짐으로 이전한다. 사용자가 명시적으로 바꾼 값은 보존한다. 예전 원본/음성 값이 다르면 더 긴 보관값으로 통합하고 무기한 값이 있으면 무기한을 보존해 갑작스러운 삭제를 피한다. 기존 자료에 새 유한 정책을 처음 적용할 때는 마이그레이션 시각부터 해당 기간을 부여하는 일회성 유예를 기록한다. 구분이 불가능한 정책을 임의로 사용자 변경 전 값이라고 단정하지 않는다.
- 전사 30일 만료는 `minutes_revisions`나 요약본을 삭제하지 않는다. DB 참조·목록 검색·내보내기·현재 버전·편집/확정 경로를 함께 분리한다. 내부 전사 참조에는 만료 상태를 표현하고 마이그레이션 후 외래키 무결성을 확인한다.
- 7일 후에는 재생 버튼만 사용할 수 없다고 표시하고 회의록 편집은 계속된다. 30일 후에는 전사 보기·원문 근거 확인·원문 기반 재생성만 제한한다. 결과 본문과 이미 계산한 논제 시작 시각은 유지한다. 원본 없는 상태에서 새 자동 근거나 시각을 만들어내지 않는다.
- 만료된 원본을 읽다가 상세 화면 전체가 오류로 바뀌면 안 된다. 가용 상태를 API로 명확히 반환하고 웹의 전사/회의록 로딩을 독립시킨다. 수동 추가 항목에는 원문 링크가 없어도 된다.
- 임베딩은 `diarization`·원본 전사 snapshot 등 중복 저장 위치까지 제거한다. 요약본에 전사 전체나 임베딩을 숨겨 영구 보관하지 않는다. 기존 저장된 회의록 본문 자체는 사용자 문서로 보존한다.
- 전체 삭제는 기존처럼 원본·파생물·전사·결과·검색 정보까지 정리한다. 실행/재시도/삭제/정리 경쟁과 늦은 결과 저장 방지를 유지한다. 자동 만료는 실행 중 작업을 임의 취소하지 않는다.
- 백업에서 복원할 때 만료 상태와 정책을 유지한다. 외부로 내보낸 파일이나 기존 오프라인 백업까지 자동 삭제했다고 주장하지 말고 운영 안내에서 범위를 구분한다.

### M2.6 키 없는 일반 사용, 설정·진단 보호

여기서 키는 현재 웹의 **소유자 키**다. 웹 소유자 인증과 서버의 Codex 구독 로그인을 혼동하지 않는다. 소유자 키 없이 웹을 사용하더라도 AI 생성에는 연결된 Codex 런타임 로그인이 필요하다.

| 기능 | 소유자 키 없는 로컬 사용자 | 소유자 인증 후 |
|---|---|---|
| 회의록·영상 요약 목록/상세/업로드/URL 입력/작업 상태/취소/재시도 | 허용 | 허용 |
| 회의록 편집·저장·재생성·내보내기·일반 자료 삭제 | 허용 | 허용 |
| 설정 조회·변경, 진단 조회·실행, 환경 경로·연결 상세·사용량 진단 | 불허 | 허용 |

- 앱 진입을 로그인 화면으로 막지 않는다. 키 입력 없이 같은 출처의 로컬 사용자 세션과 CSRF 토큰을 초기화하고, 설정·진단 진입에서만 소유자 인증을 요구한다. 최소 권한/기능 정보 외에 민감한 진단·설정 값을 일반 화면에 내려주지 않는다.
- 프런트엔드 탭 숨김만으로 구현하지 않는다. API 권한 경계를 분리하고 직접 요청해도 설정·진단이 보호되게 한다. 소셜 로그인을 나중에 연결할 수 있도록 현재 세션의 권한 확인을 한 경계에 모은다. 다중 사용자·계정별 데이터 분리는 이번 범위가 아니다.
- 루프백 바인딩, Host/Origin 검증, CSRF, SameSite/HttpOnly 쿠키, 요청 크기 제한, 안전한 파일 접근을 유지한다. 익명 사용을 위해 CORS `*`, `0.0.0.0`, CSRF 비활성화를 도입하지 않는다. 키 없는 접근은 외부 공개 서비스 모드가 아니다.
- 설정 및 진단 화면에서는 **설정이 위, 진단이 아래**다. `로그아웃`은 우상단 `LOCAL · CPU` 옆에 소유자 인증 상태일 때만 표시한다. 미인증 상태에는 필요 시 설정 로그인 진입만 제공한다.
- 로그아웃은 소유자 권한·민감 캐시를 제거하고 일반 로컬 사용자 상태로 돌아온다. 회의/요약 사용을 막거나 처리 중 워커를 중단하지 않는다. 세션 만료·로그아웃·다른 탭 변화 후에도 설정 API가 열려 있으면 안 된다. 저장하지 않은 편집 처리도 명확히 한다.

### M2.7 새 회의 입력

- `언어`, `실제 발화자 수` 입력을 제거한다. 새 웹 요청은 `language=auto`, `speakers=null`로 보내며 백엔드도 신규 일반 흐름의 자동값을 보장한다. pyannote 자동 범위는 1~12명이다. 기존 데이터의 수동 설정은 과거 실행 기록으로 보존한다.
- 회의 일시는 폼을 새로 열 때 **Asia/Seoul의 현재 날짜·시간**을 미리 입력한다. 사용자는 실제 회의 일시로 수정할 수 있다. 브라우저·서버 시간대가 UTC나 미국이어도 같은 한국 시각을 표시한다. 입력을 `+09:00`의 시각으로 해석해 저장하고 `timezone=Asia/Seoul`을 명시한다. `toISOString().slice()` 또는 브라우저 로컬 `new Date(datetime-local)`에 그대로 의존하지 않는다.
- 기존 옵션은 **`연결된 AI를 사용한 회의록 생성`**으로 바꾸고 항상 켜진 고정 상태로 표시한다. 켜지 않은 기본값·업로드별 재동의·전사 전용 선택은 새 업로드 흐름에서 제거한다. 해당 옵션 아래 기존 Codex/동의 안내 문단을 삭제한다. 상세의 새 초안 생성에도 같은 문구 정책을 적용한다.
- 서버에는 사용자가 이번 생성 요청에서 활성화된 AI 처리를 요청했다는 상태를 저장한다. 기존 `allow_external_text=false` 자료를 읽기만 했는데 자동 전송하지 않는다. 연결 실패·사용량 제한은 명확한 작업 상태로 보여주고 무료/유료 다른 공급자로 자동 전환하지 않는다. 장애 시 전사만 보존하고 작업을 끝내는 기존 복구 기능은 남긴다.
- `새 회의 업로드`는 별도 페이지 상태/라우트로 전환한다. 입력 중에는 기존 목록·선택 상세·검색 폼을 아래에 렌더링하지 않는다. 닫기/뒤로 가기로 이전 목록·필터·선택 상태를 복원하고, 업로드 성공 시 생성한 자료 또는 해당 대기열 위치를 명확히 보여준다. 뒤로 가기·새로고침·전송 실패 재시도에서도 중복 자료가 생기지 않게 한다.
- 여러 오디오 트랙의 명시적 선택, 크기/길이 검사, 진행률, 업로드 멱등성은 유지한다. 새 요약 입력에도 화면 분리·자동 인식·항상 켜진 AI 생성 원칙을 재사용한다.

### M2.8 영상 요약 탭과 YouTube 입력

#### 제품·출력

주 메뉴에 **`영상 요약`**을 추가한다. 회의 목록과 별도 목록·입력·상세를 제공하며 입력은 **파일 업로드 / YouTube 링크** 중 하나다. 회의와 동일한 음성 추출·전사를 사용하고 화면·슬라이드·자막 이미지 분석은 하지 않는다.

- 결과 이름은 UI·작업 단계·내보내기에서 **`요약본`**이다. 회의록의 결정·할 일·담당자·미결 질문 틀을 그대로 재사용하지 않는다.
- 시사·경제 영상에 맞게 전체 핵심 요약, 주제별 설명, 영상에서 실제 언급한 주요 수치·시점·주장·전망을 정리한다. 없는 항목은 억지로 채우지 않는다. 다른 종류의 대화 영상도 일반 주제 요약으로 처리한다.
- 설명자의 주장·의견·예측은 그 출처를 드러내고 확정된 사실과 구분한다. 숫자는 단위·대상·기준 기간을 보존한다. 정치적 지지·우열 판단이나 매매 권유를 생성하지 않고, 요약기가 별도로 최신 사실을 검증한 것처럼 쓰지 않는다. 외부 뉴스 검색·금융 데이터 조회는 이번 작업에 넣지 않는다.
- 영상 제목·채널·게시일과 분석 시각을 구분한다. 게시일을 모르면 미상으로 두고 업로드 일시를 발언의 기준 날짜로 임의 대체하지 않는다. `오늘/내년`이 불명확하면 원표현을 유지한다.
- 주제별 **시작 시간만** 간결하게 보여준다. 단어 근거·개별 검토 상태·화자 수정·본문 편집·확정 버튼은 없다. 서버에서도 요약본에 회의록 편집/확정 API를 적용할 수 없게 한다. 생성 실패 재시도와 명시적 새 요약 생성은 별개 기능이며 새 버전으로 저장할 수 있다.
- 파일은 로컬 음성의 해당 시간, YouTube는 로컬 음성의 해당 시간으로 이동한다. 원본 영상 링크는 상세 전체에 하나만 제공한다. 로컬 음성이 만료돼도 제목·요약·시간은 남고 YouTube 원본 링크는 사용할 수 있다. 별도 iframe 삽입을 위해 기존 CSP를 완화하지 않는다.
- 문서 종류와 입력 종류를 분리한다: 예를 들어 `document_kind=meeting|video_summary`, `source_kind=file|youtube`. 기존 자료는 `meeting/file`로 호환한다. 기존 테이블을 모두 이름 바꾸기보다 작은 확장과 종류별 스키마/렌더러를 사용한다. 원본 획득·전사·큐·삭제·보관·내보내기 기반은 공유한다.
- 두 탭의 자료는 목록에서 구분하되 **새 자료 분석 FIFO는 하나이며 AI 재생성 FIFO는 독립적**이다. 다른 탭의 작업 때문에 대기하는 경우에도 현재 실행 작업과 실제 전체 순번을 알 수 있게 표시한다. 영상 다운로드 역시 같은 실행 슬롯에서 수행하고 별도 병렬 다운로드 큐를 만들지 않는다.

#### YouTube 획득과 안전 경계

- 기본 획득기는 `yt-dlp` 어댑터다. URL 제출은 빠르게 자료·작업을 등록하고, 워커가 정보 확인 → 음성 다운로드 → 기존 파이프라인으로 진행한다. `SOURCE_CHECK`/`DOWNLOAD` 등의 단계와 오류를 UI에 표시한다. 웹 요청 안에서 긴 다운로드를 끝낼 때까지 기다리지 않는다.
- 지원 입력은 HTTPS의 `youtube.com/watch?v=...`, `youtu.be/...`, `/shorts/...`, `/live/...`의 **단일 영상**이다. 허용 호스트·유효 영상 ID를 파싱해 정규 URL로 다시 만든다. 허용하지 않은 하위 도메인·사용자 정보·비표준 포트·위조 호스트·IP 주소·임의 사이트는 거절한다. `list`, `si`, `t`, `start` 등은 처리 대상 확장이나 시작 오프셋으로 사용하지 않고 전체 영상 기준으로 정규화한다.
- 채널·재생목록 일괄 처리, 진행 중/예정 라이브, 유료/멤버십/로그인 필요/DRM 보호 영상은 지원하지 않는다. 종료된 라이브는 길이와 접근 조건이 확인되면 일반 단일 영상으로 처리한다. 삭제·지역/연령/봇 제한 등 접근 실패는 이유와 파일 업로드 대안을 표시하고 우회하지 않는다.
- 음성 트랙만 받으며 영상 프레임·썸네일·댓글·자막을 요약 입력으로 대신 사용하지 않는다. 제목·설명만 확보하고 전사에 성공한 것처럼 요약하지 않는다. 오디오가 없거나 길이를 안전하게 확인할 수 없으면 명시적으로 중단한다.
- 길이 7,200초·수신 파일 2,000,000,000바이트 제한은 정보 확인과 수신 과정 및 `ffprobe` 검사에 모두 적용한다. 파일 크기 메타데이터가 없을 때도 누적 수신량·디스크 사용량을 제한한다. 초과 영상을 조용히 2시간으로 잘라 전체 요약처럼 내보내지 않는다.
- 재시도/조각 수/전체 소요시간을 유한하게 제한한다. 다운로드 중 취소·서버 재시작·삭제는 기존 프로세스 그룹과 실행 fencing을 사용하며 임시 파일을 정리한다. 수신 완료·해시 확인 전에는 정상 원본으로 공개하지 않는다. 동작 중인 JS 런타임·FFmpeg도 취소 대상이다.
- URL 허용 목록만으로 SSRF 방어가 끝났다고 보지 않는다. 추출 결과·리디렉션·DNS가 향하는 사설/루프백/link-local/메타데이터 주소 접근을 차단하고, 필요한 YouTube/CDN 요청만 허용하는 획득 경계를 검증한다. generic extractor·임의 URL 폴백은 없다. ASR 워커의 오프라인 모델 정책은 유지한다.
- 다운로더는 고정 인자 배열로 호출하고 사용자 URL·제목을 셸·출력 경로·명령으로 결합하지 않는다. 서버 생성 파일명, 독립된 임시 디렉터리, 제한된 환경을 사용한다. 개인 yt-dlp 설정·플러그인·브라우저 쿠키·인증·프록시를 자동 상속하지 않는다. 필요한 통신과 무관한 로컬 파일 접근도 제한한다.
- 버전을 잠그고 YouTube 지원에 필요한 `yt-dlp-ejs`와 지원 JS 런타임을 Ubuntu 설치·진단·릴리즈에 포함한다. 런타임은 지원 버전을 확인한 Deno 하나로 정해 경로/버전을 기록한다. 처리 도중 자동 업데이트·원격 구성요소 설치를 하지 않는다. 라이선스 고지도 갱신한다.
- 재사용·처리가 허용된 영상만 다루도록 사용 범위를 문서화한다. 공개 URL이라는 이유만으로 다운로드·재배포 권한을 보장하지 않는다. 테스트 자료는 권한과 원본 주소·선택 구간을 기록하고 원본 미디어를 Git에 넣지 않는다.
- 콘텐츠 제목·전사·외부 메타데이터는 전부 비신뢰 데이터다. Codex에게 다운로드·웹 검색·셸 실행 권한을 주지 않고 기존 텍스트 전용 생성 격리를 유지한다.

#### 실제 품질 확인과 검증 예산

- 먼저 고정된 전사·화자·시각 fixture와 mock 생성기로 구조/보안/웹을 시험한다. 실제 품질 평가는 수동으로 논제·농담/미결·시작 허용 구간을 표시한 짧은 자료로 별도 수행한다. mock이나 문자열 규칙 시험만으로 AI의 의미 판단을 검증했다고 하지 않는다.
- 기존 허가된 3분 내외 한국어·영어 자료와 출력이 있으면 우선 재사용한다. 실제 모델은 관련 화자/정렬 경로를 바꾼 경우에만 필요한 짧은 자료를 다시 실행한다. 자연 12인 회의 정확도 개선을 측정하지 않았으면 그렇게 보고한다.
- 실제 Codex 확인은 교정된 전사로 회의록/영상 요약을 각각 확인하고, 같은 전사를 사용해 프롬프트 변경 전후를 비교한다. 전체 전사를 다시 돌려 호출을 시험하지 않는다. 호출 횟수·시간·입력 해시의 명시적 예산 안에서만 실행한다.
- YouTube 실제 연결은 재사용 권한을 확인한 3분 내외 단일 영상 하나로 정보 확인·음성 획득·시간 매핑을 점검한다. 나머지 제한/실패는 fixture로 검사한다. 새 라이브 네트워크 실행 예산과 의존성 준비를 먼저 기록하며 차단을 만났다고 URL을 무작위로 바꾸거나 쿠키를 가져와 반복 시도하지 않는다.
- 기존 예산·로그인·자료 권한으로 수행할 수 없는 실제 검사는 `BLOCKED`로 남긴다. 가능한 오프라인 구현을 진행하되 실제 YouTube/모델/CLI 성공이나 M2 전체 완료를 만들어내지 않는다. 프롬프트 변경 후 관련 없는 옛 CLI PASS를 새 품질 증거로 사용하지 않는다.
- **검증 위임은 기본 두 묶음**이다. `M2-A`: W1~W3의 전사/결과 버전/보관/편집 계약. `M2-B`: W4~W6의 인증/입력/YouTube/웹 통합과 최종 증거. 요청 ID는 기존 ID와 중복되지 않게 만들고 workflow의 고정 커밋·범위·명령·예산·알림 소비를 따른다.
- 마스터는 작업마다 영향 범위의 최소 검사를 한다. 최종 저비용 전체 회귀는 마스터 또는 검증자 한쪽에서 한 번 실행하고 다른 쪽은 같은 증거를 검토한다. `release`에 포함되는 검사를 별도 전체 실행으로 연이어 중복시키지 않는다. 수정 후에는 실패 항목·관련 범위만 재검증한다.
- 120분 soak, 반복 전체 모델 실행, 여러 검증 세션, 검증자 재귀 위임은 포함하지 않는다. 정상 완료 알림에 답장하지 않고 기존 소비 도구를 사용한다. `.workflow` 증거가 없는 새 환경은 과거 통과 이력을 재창작하지 않는다.

### M2.10 완료·인수인계

M2의 완료는 체크박스뿐 아니라 구현 결과·범위 검증·실제 실행 증거·외부 차단 상태를 대조해 판단한다. 미완료 기능을 범위 밖으로 바꾸거나 필수 검사를 삭제해서 끝내지 않는다. 사용자 데이터에 파괴적 시험을 하지 않는다.

완료 시 이 문서의 현재 상태/구현 계약/완료 표를 실제로 갱신하고 활성 작업은 정리한다. README에는 키 없는 로컬 사용의 범위, 설정/진단 로그인, 연결된 AI의 실제 Codex 인증, 자료 보관과 만료 후 제한, YouTube 지원/제한·의존성, Ubuntu/Windows 실행법을 반영한다. 작업 규약이 바뀌지 않았다면 workflow는 불필요하게 고치지 않는다. 상세 증거·차단·재개점은 `.workflow`에 둔다.

설계 참고: [Codex 명령 및 파일 기반 goal](https://developers.openai.com/codex/cli/reference/), [yt-dlp 공식 의존성·옵션](https://github.com/yt-dlp/yt-dlp#dependencies), [OWASP SSRF 방어](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). 설치 시 버전과 실제 지원 조건은 해당 공식 문서로 다시 확인한다.

## 후속 프론트 정리

영상 목록에서 `YouTube 영상 요약`과 `새 영상 요약`을 같은 단계의 버튼으로 제공한다. YouTube 버튼은 파일 업로드 버튼 왼쪽에 있으며 각 입력 화면으로 바로 이동한다. 두 목록의 소개 문구를 제거하고 YouTube 입력 폼의 버튼 스타일을 통일했다.

입력의 처리 시작 버튼은 오른쪽, 입력·자료 상세의 뒤로가기 아이콘은 우상단에 둔다. 회의록 제목과 버전/편집 조작부를 분리하고 버튼 글자의 강제 줄바꿈을 방지한다. 회의록의 전사문 패널과 `이 버전 Markdown`·`이 버전 텍스트` 링크는 제거했다. 현재 결과 내보내기와 영상 요약 내보내기는 유지한다.
상세 상단의 새로 불러오기/생성·전체 삭제는 한 조작 줄에 배치하고, 좁은 화면에서만 항목 단위로 감싼다.

공용 회의 목록은 `회의록`으로 표기한다. 영상 목록은 `VIDEO LIBRARY`로 구분하며 검색/표시 입력 높이는 동일하다. 검색·표시 입력 오른쪽에 전체 분석 대기 수와 처리 상태를 표시하고 실행·취소 처리 중에는 작은 원형 표시를 사용한다. 실행 카드의 테두리를 강조하며 완료 카드에는 처리 시간을 숨긴다. 동작 줄이기 설정에서는 움직임을 멈춘다.

## 회의록 정리 개선

재논의는 다른 논제의 구간이 사이에 있을 때만 분리하며 단순 발언/근거 간격은 합친다. 새 AI 생성은 짧은 논제 제목(최대 60자)을 필수로 쓰고, 제목 없는 과거 문서는 본문을 잘라 제목으로 표시하지 않는다. 의미 있는 제목은 편집하거나 새 초안 생성으로 저장한다. 기존 저장 버전을 자동 재생성하거나 덮어쓰지 않는다. 웹의 논제별 시작/재논의 재생은 유지하되 회의록 Markdown·텍스트에서는 시작 시각 줄을 제외한다. 본문에서 의미 있는 실제 기한·일시는 보존한다. 재생기는 회의 개요·요약 위에 두고, 생성·내보내기는 `AI를 사용한 요약 회의록 생성` 박스에 묶는다. 최종 확정 버튼 없이 수정본 저장을 사용한다.

회의록 버전은 최초 `초안`, 이후 `버전02_0927`처럼 버전 번호와 저장일(KST MMDD)을 통합 표시한다. 별도 상태 배지는 표시하지 않는다. 논제 추가 버튼에는 위 간격을 두며 생성 박스는 `초안 재생성`·`텍스트 내보내기`·`Markdown 내보내기` 순서와 같은 버튼 스타일을 사용한다. 영상 요약 탭에도 메뉴 아이콘을 표시한다.

논제 제목은 본문 발췌가 아닌 2~6단어의 주제 명사구로 생성한다. 텍스트 내보내기는 원문 특수문자를 유지하고 Markdown은 문법상 필요한 이스케이프만 적용한다. 두 다운로드 형식은 Windows 사용자를 위해 CRLF를 사용한다. 논제 이동은 접근 가능한 이름이 있는 위/아래 화살표이며 삭제와 함께 오른쪽에 배치한다.

재생성·자료 삭제·보관 정책·미저장 변경 확인은 사이트 모달을 사용하며 취소/Escape로 작업을 중단한다. 탭 닫기·새로고침의 미저장 경고는 브라우저 기본 보호를 유지한다. 실제 사용 서버는 작업 처리기를 활성화해야 대기열이 실행된다. `MINUTES_WORKER_ENABLED=false`는 격리된 화면 시험에서만 사용한다.

재생성은 음성을 다시 분석하지 않고 저장된 전사로 AI 요약만 별도 실행한다. 명시적 재생성 결과는 새 기본 버전이 되며 이전 수정본은 보존한다. 생성 도중 저장된 별도 수정본이나 새 전사는 덮어쓰지 않는다. 편집 중이 아니면 완료된 최신 결과를 자동으로 표시하고, 내보내기는 현재 선택한 버전을 사용한다. 최초 버전만 초안으로 표기한다. 제목을 비운 파일은 요약 생성 시 AI 제목을 저장하며, 제목을 비운 YouTube는 원본 제목을 사용한다. 취소 전 사이트 모달로 확인한다.

영상 요약 상세는 회의록과 같은 본문·주제 카드·버튼 스타일을 사용하며 줄바꿈을 보존한다. 음성 재생기는 핵심 요약 위에 둔다. 원본 영상 링크는 전체에 하나, 요약 재생성·텍스트·Markdown 내보내기는 생성 박스에 모은다. 영상의 버전 선택·표시는 제거하고 최신 요약만 제공한다. 내부 저장 이력은 보존하며 내보내기는 화면에 표시된 요약에 연결된다.

내보내기 파일명은 회의록 `minutes_verNN_MMDD.md/txt`, 영상 요약 `summary_verNN_MMDD.md/txt`이며 선택한 결과의 버전 번호와 저장일(KST)을 사용한다. 본문과 파일명은 같은 결과를 기준으로 만든다.

영상 요약은 별도의 수치·주장·전망 목록 없이 주요 주제에 내용을 통합한다. 새 생성은 각 주제 본문에 수치·단위·기간과 발언 주체를 보존한다. 기존 저장본은 변경하지 않고 별도 주장 목록의 표시·내보내기만 제외하며 새 구성으로 정리하려면 요약을 재생성한다. 회의록과 영상 모두 텍스트·Markdown 내보내기에서 재생 시작 시각을 제외하고 웹의 시각·재생 버튼은 유지한다.

회의록·영상 요약의 읽기 화면과 텍스트·Markdown 내보내기는 마침표로 끝나는 문장을 줄바꿈한다. 소수점·URL·일반적인 영문 약어와 기존 문단을 보존하며 저장 원문·편집 입력·제목은 변경하지 않는다.

### M3.2 Gemini 키 저장과 비밀 경계

#### 저장 위치와 교체

기본 위치는 **`<config_dir>/.apikey/gemini.json`**, 기본 설정 경로를 쓰면 **`~/.config/local-meeting-minutes/.apikey/gemini.json`**이다. `MINUTES_CONFIG_DIR` 변경도 따른다. `.apikey`를 실행 CWD나 Windows 저장소에 만들지 않으며 정적 웹·업로드·산출물 디렉터리 밖에 둔다.

- 현재 키 하나만 저장한다. 같은 고정 파일에 키와 무작위 `credential_revision`을 기록하며 새 키 저장 시 기존 내용을 원자적으로 교체한다. 원문 키를 DB·설정 JSON·작업 snapshot·환경 파일에 중복 저장하지 않는다. 키의 접두어·끝자리·해시를 식별자로 공개하지 않는다.
- 디렉터리 `0700`, 파일 `0600`, 제한된 umask와 파일 소유자를 확인한다. 링크·경로 탈출·잘못된 파일 종류를 거부하고 안전한 디렉터리 핸들/파일 생성으로 경합을 방어한다. 같은 private 디렉터리의 제한된 임시 파일에 쓰고 fsync → atomic replace → 디렉터리 동기화로 공개한다. 기존 파일을 먼저 truncate하거나 삭제하지 않는다.
- 교체 잠금과 예상 revision 검사를 적용한다. 두 설정 탭이 동시에 다른 키를 저장하면 충돌을 알리고 임의로 마지막 요청을 덮어쓰지 않는다. 비정상·빈 입력이나 디스크 오류는 기존 키를 훼손하지 않는다. 성공 후 이전 키 파일·자동 백업·편집기 사본을 만들지 않고 실패/중단 임시 파일을 정리한다.
- 특정 접두어·고정 길이만으로 Gemini 키의 유효성을 확정하지 않는다. 입력 크기·제어문자 등 기본 검사를 하고 실제 인증·모델 접근은 별도의 제한된 연결 검사로 확인한다. 저장 성공과 인증 성공은 다른 상태다. 새 키를 저장해도 전역 AI 선택을 자동 변경하지 않는다.
- 키 삭제는 명시적인 별도 동작과 사이트 확인 모달로 제공한다. 빈 입력을 삭제로 해석하지 않는다. 삭제 후 Gemini는 비활성 상태가 되지만 회의록·선택 기록·다른 AI 인증을 삭제하지 않는다. 로컬 삭제/파일 교체가 Google의 키 폐기나 디스크의 물리적 완전 삭제를 대신한다고 안내하지 않는다.

#### 웹·API·배포

- 설정의 키 입력은 비밀번호형 입력이며 새로 열면 항상 비어 있다. 저장 후 `등록됨`과 연결 상태·갱신 시각만 표시한다. 기존 키 조회/보기/복사 API와 UI는 만들지 않는다. 저장 성공·탭 이탈·로그아웃·소유자 세션 만료 때 입력 메모리를 비우고 실패 응답에도 키를 반사하지 않는다.
- 키 저장/삭제/연결 검사 및 AI 설정 변경은 **소유자 권한 + CSRF/Origin 검증**을 요구한다. 일반 사용자가 직접 API를 호출해도 불가능해야 한다. GET은 비밀 없는 상태만 반환하며 설정 응답은 `no-store`다.
- `SecretStr` 등 입력 표현 보호만 믿지 않는다. FastAPI/Pydantic의 422 검증 오류에 들어가는 `input`, 예외 문자열, 공급자 HTTP 오류·헤더, 로그/진단/테스트 trace도 원문을 누출하지 않도록 별도로 정제한다. URL query·CLI 인자·프롬프트·브라우저 저장소·Vite 변수·HTML 데이터 속성에 키를 넣지 않는다.
- `.gitignore`에 모든 위치의 `.apikey/` 제외를 추가하고 추적 여부를 검사한다. 릴리즈 수집기·백업/복원·진단 묶음·Windows/WSL 동기화는 비밀 디렉터리와 관련 임시 파일을 명시적으로 거부/제외한다. 설정 경로가 변경되거나 private 파일이 공개 디렉터리 아래에 잘못 놓인 경우도 시험한다. 이미 추적된 비밀은 ignore만으로 해결되지 않으므로 원문을 출력하지 않고 소유자에게 폐기/교체가 필요함을 알린다. Git 이력 강제 재작성은 하지 않는다.
- “업로드하지 않음”은 키 파일을 Git·공유·백업·모델 입력 파일로 보내지 않는다는 뜻이다. 최초 입력은 브라우저에서 로컬 서버로 전달되며, Gemini 사용 시 키는 Google HTTPS API의 인증 수단으로만 전달된다. 네트워크 인증 자체가 없는 것처럼 설명하지 않는다. 소스/미디어/다른 공급자에는 전달하지 않는다.
- 파일 권한은 같은 OS 소유자나 root까지 막는 암호화가 아니다. 이 한계를 README에 짧게 명시하고 암호화한 것처럼 표시하지 않는다. 실제 키·CLI 토큰은 개발 세션의 문맥·`.workflow` 증거·스크린샷에도 넣지 않는다.

### M3.3 전역 AI 설정과 선택 가능 상태

설정 화면에 `Gemini API`, `Codex CLI`, `Claude CLI` 세 항목을 항상 표시한다. 내부 ID는 `gemini_api`, `codex_cli`, `claude_cli`로 고정한다. 공급자별 설치·인증·모델 상태와 사용 불가 이유를 보여주고 **하나만 활성 AI로 저장**한다.

| 상태 | 선택 정책 |
|---|---|
| API 키 없음 / CLI 미설치 / 런타임 로그인 없음 | 해당 항목 비활성, 필요한 설정 안내 |
| 잘못된/만료된 인증, 지원하지 않는 CLI 버전·격리 또는 모델 | 비활성, 재인증/설치/설정 안내 |
| 새 키의 연결 확인 전·검사 중 | 선택 보류. 이미 저장한 전역 선택을 다른 AI로 바꾸지 않음 |
| 인증과 해당 기능에 필요한 모델·실행 조건 확인됨 | 선택 가능. 남은 사용량 전체를 보증하는 상태는 아님 |
| 일시적 네트워크 장애·속도 제한·사용량 소진 | 인증 없음과 구분. 기존 선택은 보존하고 생성 가능 여부/재시도 상태를 별도 표시 |

- 설정은 SQLite의 비밀 없는 단일 정책 레코드에 영속 저장한다. 최소 `active_provider`, 공급자별 명시적 모델 설정, `revision`, 갱신 시각을 둔다. 브라우저 localStorage나 서버 시작 시 읽은 환경 변수만 바꾸는 방식은 안 된다. 앱·워커 재시작과 여러 탭에서 일관되어야 한다.
- 공급자를 저장할 때 서버가 enum·권한·최신 준비 상태·예상 설정 revision을 검사한다. 프런트엔드의 disabled만으로 보호하지 않는다. 로그인 만료가 UI 조회 뒤 발생한 경우도 실제 실행 직전에 재검사한다.
- 인증 검사는 **실제 Ubuntu/WSL 워커 사용자와 전용 런타임 환경**에서 한다. Windows 호스트에 로그인돼 있거나 파일 하나가 존재한다는 이유만으로 준비됐다고 간주하지 않는다. 검사 결과에는 원문 키·토큰·계정 이메일을 포함하지 않는다.
- 화면 조회/일반 상태 polling에서 생성 API를 호출하지 않는다. 파일 상태·공식 CLI 로그인 상태·캐시된 모델 정보를 먼저 확인하고, 필요한 원격 검사는 소유자의 명시적 연결 확인에서 짧은 timeout/TTL/예산으로 실행한다. 실제 한도는 알 수 없으면 미상으로 표시한다.
- 기존 설치의 기본 공급자는 `codex_cli`로 이전하고 기존 모델·경로·제한을 유지한다. 인증이 없으면 선택된 Codex를 사용 불가로 표시할 뿐 Gemini/Claude로 자동 전환하지 않는다. 새 설치도 다른 공급자를 몰래 선택하지 않는다.
- 준비된 AI가 없어도 목록·기존 결과·수동 편집·내보내기·로컬 음성 처리까지 막지 않는다. AI 단계는 명확하게 차단하고 설정 연결/취소/전사만 종료로 복구한다. 신규 입력의 AI 생성 옵션을 다시 사용자별로 끄게 만들지 않는다.
- 일반 화면에는 필요한 경우 활성 AI의 표시 이름·생성 가능 여부·설정 필요 여부만 제공한다. 비밀·환경 경로·상세 진단은 소유자 화면에 남긴다. 예전 `allow_external_text=false` 자료는 단순 열람이나 설정 변경만으로 전송하지 않는다.

### M3.4 공통 공급자 경계와 세 어댑터

작은 공통 인터페이스와 공급자 registry/factory를 둔다. 예를 들어 `capabilities`, `check_ready`, `generate_json`, 정제된 `usage/error` 계약을 공유한다. 파일명은 기존 구조에 맞게 정하되 공통 경로가 특정 공급자의 private 구현을 직접 가져오지 않게 한다.

- 현재 `codex_provider.py`의 공통 지침·공통 예외·구조 검증을 공급자 중립 모듈로 분리한다. 실제 전송, 인증, schema 변환, 응답 포맷, 토큰/문맥 제한은 어댑터의 책임이다. 서비스별 분기문을 회의/영상/웹 화면마다 복제하지 않는다.
- 공통 문서 스키마와 원문 ID/시각·한국어·숫자/날짜·논제 검증을 유지한다. 공급자별 JSON Schema 지원 범위가 다르므로 현재 Codex용 `strict_schema()`를 모든 공급자에 그대로 적용하지 않는다. 전송 schema와 정본 검증 schema의 변환을 계약 시험으로 연결한다.
- 실제 모델 ID와 지원 capability를 설정/버전으로 명시한다. Gemini·Claude 모델 이름을 기존 `codex_model`에 넣거나 무조건 같은 reasoning 옵션을 보내지 않는다. 세 공급자 모두 회의/영상/긴 입력에 필요한 구조화 출력을 지원하는 모델을 P0에서 확인한다. 최신 모델이나 무료 한도를 기억만으로 고정하지 않는다.
- 문맥 제한은 공급자별 모델 정보와 보수적 입력·출력 여유로 계산한다. Gemini/Claude가 `codex-home/models_cache.json` 때문에 실패하지 않아야 한다. 원문 전체가 한 번에 안 들어가면 기존 발언 단위 분할/후반 번복 통합을 재사용하며 뒷부분을 버리지 않는다.

#### Gemini API

- 서버에서 공식 **`google-genai`** SDK의 고정 버전을 사용한다. 명시적으로 전달한 키만 사용하고 `GOOGLE_API_KEY`/`GEMINI_API_KEY` 등 외부 환경이나 다른 Google 계정 자격 증명으로 자동 대체하지 않는다. 누락된 선택적 의존성이 앱 전체 또는 Codex를 깨뜨리지 않게 한다.
- 필요한 전사 텍스트·허용된 메타데이터만 텍스트 생성 API로 보낸다. 원본 음성/영상·임베딩·전체 로컬 파일·YouTube 링크를 Gemini Files/영상 분석 API로 보내는 기능은 넣지 않는다. 외부 검색·도구 실행도 사용하지 않는다.
- 공식 API endpoint와 TLS 검증을 사용하고 사용자 입력 endpoint나 인증 헤더를 유지한 임의 리디렉션을 허용하지 않는다. 키가 URL·debug 로그에 남지 않는 인증 경로를 사용한다. SDK의 암묵적 retry/timeout도 앱의 유한 예산에 맞춘다.
- 구조화 JSON을 공통 문서로 검증한다. 인증/권한 오류, 모델 접근 불가, 429, 서버 오류, 안전 차단, 빈 응답, 출력 길이 초과를 구분하며 불완전 응답을 정상 요약으로 저장하지 않는다.
- 무료/유료 여부는 키 모양으로 알 수 없다. 설정에서 적용 서비스의 비용·데이터 처리 조건을 확인할 수 있게 하고 사용자 허가 없이 결제를 활성화하지 않는다. 무료 Gemini의 기밀/민감정보 제한을 안내하며 실제 시험에는 허가된 공개 또는 가상 전사만 쓴다. 설정 단계의 고지를 사용하고 업로드별 동의 체크박스를 다시 도입하지 않는다.

#### Codex CLI

기존 구독 전용 `CodexCliProvider`의 전용 HOME·CODEX_HOME·stdin 입력·JSON 출력·도구 차단·버전/격리 검사·일회성 실행을 보존해 공통 인터페이스에 연결한다. 현재 검증된 `0.157.1`을 공급자 확장만을 이유로 강제 업그레이드하지 않는다. API 키 기반 유료 호출이나 개발 세션 인증을 대신 사용하지 않는다.

#### Claude CLI

- **공식 Claude Code CLI의 비대화형 `claude -p`**를 사용한다. 로컬 소유자가 해당 CLI의 지원 로그인 절차로 인증한다. OAuth 토큰을 추출해 별도 Anthropic API 클라이언트에 재사용하거나 개인 개발 세션의 인증 파일을 복제하지 않는다.
- 전용 Linux 런타임 HOME과 `CLAUDE_CONFIG_DIR`를 준비하고 설치·로그인·상태 검사·실행이 모두 같은 환경을 사용하게 한다. Windows 로그인 상태를 WSL 로그인으로 간주하지 않는다. Claude가 없어도 나머지 공급자와 앱은 사용 가능하다.
- 공식 문서상 `--bare`는 구독 OAuth 인증을 읽지 않는 모드이므로 구독 CLI 실행에 무조건 붙이지 않는다. 대신 선택한 CLI 버전의 실제 지원 옵션으로 도구/MCP/hooks/플러그인/스킬/브라우저/개발 지침 상속을 차단하고 검증한다. 빈 작업 디렉터리·제한된 환경만으로 충분하다고 가정하지 않으며 격리를 증명할 수 없으면 해당 공급자를 비활성화한다.
- `ANTHROPIC_API_KEY`, 다른 클라우드 공급자/endpoint 설정 등이 비대화형 인증을 바꾸지 않게 환경을 정제한다. 별도 유료 API로의 폴백이나 `--dangerously-skip-permissions`를 해결책으로 사용하지 않는다.
- 전사와 프롬프트는 stdin으로 전달하고 지원되는 JSON 출력/JSON Schema 옵션을 사용한다. CLI의 결과 envelope에서 오류·완료 상태와 `structured_output`을 확인한 뒤 공통 로컬 검증을 한다. 종료 코드 0 또는 단순 자연어 응답만으로 성공 처리하지 않는다.
- 호출마다 새 실행을 사용하고 가능한 세션 비보존 옵션을 버전별로 검증한다. CLI가 남기는 전사 포함 세션/임시 파일도 기존 보관 정책과 삭제 범위에 포함한다. 프로세스 트리 취소·stdout/stderr 크기·시간 제한·내부 turn/retry 제한을 검증한다. 설치/로그인/진단 스크립트와 릴리즈 고지를 추가하되 실제 계정 로그인은 소유자가 한다.

### M3.5 모든 AI 기능의 적용 범위

| 경로 | 전역 AI 설정 적용 |
|---|---|
| 회의 파일의 최초 회의록 생성 | 새 분석 요청에 고정한 공급자 사용 |
| 파일 및 YouTube 영상의 최초 요약 | 같은 공통 생성 경로 사용. YouTube 획득 자체는 기존 로컬 처리 |
| 회의록 초안 재생성·영상 요약 재생성 | 요청 당시 활성 AI로 새 snapshot 생성. 기존 결과/편집본 보존 |
| 제목 없는 파일의 AI 제목 | 해당 문서를 만드는 동일 응답에서 생성. 별도 Codex 호출 금지 |
| 긴 입력의 후보 추출·여러 청크·최종 통합 | 한 작업의 동일 공급자/모델/프롬프트 snapshot 사용 |
| JSON 구조 보정·네트워크 재시도 | 동일 공급자와 영속 예산 사용. 다른 AI로 자동 폴백 금지 |
| 명시적 연결 생성 시험·사용량 진단 | 선택한 검사 대상 어댑터 사용, 제품 생성과 분리된 예산/표시 |

STT/정렬/화자 임베딩, 시각 계산, 사용자 본문 편집, 검색, 내보내기에는 새 외부 AI 호출을 만들지 않는다. 새 AI 기능을 추가할 때도 공통 실행 경계 외부의 직접 호출은 계약 테스트와 코드 점검 대상이다. 제품 설정이 개발용 Astra/Sol 세션의 모델을 바꾸지는 않는다.

### M3.6 설정 변경·대기열·키 교체·캐시

**전역 선택은 새 요청부터 적용하며, 등록된 작업의 공급자를 실행 도중 바꾸지 않는다.** 이는 과거/대기 중 전사 내용이 설정 변경만으로 다른 회사에 전송되는 것을 방지한다.

1. 파일은 업로드가 완료되어 분석 작업을 등록할 때, YouTube는 URL 작업 등록 때, 재생성은 요청 등록 때 **비밀 없는 `GenerationConfigSnapshot`**을 같은 DB 트랜잭션으로 고정한다. 최소 공급자 ID·명시적 모델·설정 revision·프롬프트/schema/어댑터 버전·문맥/출력/호출 한도를 담는다. AI 단계가 시작될 때마다 전역 설정을 다시 읽어 공급자를 바꾸지 않는다.
2. 동일 idempotency key의 응답 유실 재요청은 원래 작업과 snapshot을 반환한다. 그 사이 설정이 바뀌어도 두 번째 작업이나 다른 공급자 요청을 생성하지 않는다. 대기/실행/차단 작업의 일반 재시도도 원래 공급자를 유지한다. 현재 AI를 적용하려면 명시적으로 새 생성 요청을 만들어 저장된 전사를 재사용한다.
3. 키·CLI 토큰은 snapshot에 넣지 않는다. 공급자의 실제 자격 증명은 시도 시작 시 전용 저장소에서 읽는다. 아직 시작하지 않은 Gemini 작업은 교체된 새 키를 사용한다. 이미 외부 전송 중인 호출은 이전 키로 끝날 수 있음을 구분한다. 긴 작업의 호출 사이 키 교체/삭제가 확인되면 `AI_CREDENTIALS_CHANGED` 등으로 멈추고 명시적 재시도를 받으며, 옛 키를 디스크에 보관하거나 서로 다른 키로 조용히 계속하지 않는다.
4. 설정 변경은 소유자 설정/상태 캐시를 무효화하고 프로세스 간에 반영한다. API 서버나 워커가 시작 시 생성한 `Settings` 객체만 참조해 새 선택을 무시하지 않게 한다. 관련 없는 보관 설정 revision 변화가 진행 중 생성 설정을 깨뜨리지 않도록 별도 revision을 둔다.
5. 생성 identity와 전체/청크 checkpoint는 공급자·모델·공통/공급자 프롬프트·schema·어댑터 버전·입력 snapshot·실행 옵션을 포함한다. 같은 전사를 Gemini로 요청했는데 Codex의 중간 결과/완성본을 그 응답처럼 반환하지 않는다. 키 원문·키 해시는 생성 identity에 넣지 않는다. 무작위 credential revision은 키 교체 감지용일 뿐 키 자체를 추정할 자료가 아니다.
6. 결과와 usage에 실제 호출 공급자·설정 모델·확인 가능한 실제 모델·생성 설정 revision을 서버가 기록한다. LLM에게 자기 공급자를 쓰게 하지 않는다. 공급자가 실제 모델 정보를 주지 않으면 추정해 채우지 않는다. 과거 결과는 호환 필드/미상 상태로 읽고 현재 선택으로 출처를 덮어쓰지 않는다.
7. 기존 미완료 작업은 당시 Codex 설정을 복구 가능한 범위에서 고정한다. 마이그레이션 뒤 갑자기 Gemini/Claude로 보내거나 예산을 0부터 다시 만들지 않는다. 복구 불가능하면 명확한 설정 확인 상태로 두고 저장된 전사로 새 생성을 안내한다. 기존 완료 문서·수동 수정·선택 버전·재생성 중 편집 충돌 계약은 유지한다.
8. 분석/AI 재생성 **두 lane은 유지**한다. 같은 공급자의 네트워크 호출과 CLI 인증 갱신은 초기에는 공급자별 동시 1개로 제한하는 공통 프로세스 간 잠금/lease를 사용한다. 이 제한은 ASR을 직렬로 되돌리는 것이 아니다. 다른 공급자의 기존/신규 작업은 각 lane 안에서 진행할 수 있다. 대기는 취소 가능하며 네트워크 중 DB 쓰기 트랜잭션을 잡지 않는다. 재시작·프로세스 사망 후 잠금 복구를 검사한다.
9. 공통 오류는 인증 필요/인증 무효/모델 불가/격리 불가/속도·사용량 제한/네트워크/불완전 출력/예산 소진으로 구분한다. 인증 오류를 무한 retry하지 않는다. 429의 대기 안내와 유한 backoff를 적용하고 키 교체가 프로젝트 쿼터를 초기화한다고 간주하지 않는다. SDK·CLI 내부 retry까지 포함해 무제한 호출이 생기지 않게 한다.
10. 외부 호출 전 영속 예약, 결과 저장 전 attempt·취소·삭제 검사, 자식 종료 확인을 유지한다. timeout/cancel 뒤 외부 처리가 이미 진행됐을 수 있으므로 정확히 한 번 과금이나 취소 시 사용량 환불을 보장하지 않는다. 키·공급자 변경과 재시작으로 이미 소비한 작업 예산을 초기화하지 않는다. 앱 관측 사용량과 전체 계정의 잔여량은 별개로 표시한다.

### M3.7 API·화면·운영 인수 범위

API 경로는 아래 형태를 기준으로 기존 구조에 맞게 구현한다. 설정과 키의 변경 revision은 구분하며 반환값에 비밀 필드는 존재하지 않아야 한다.

| API 예시 | 권한·역할 |
|---|---|
| `GET /api/settings/ai` | 소유자. 선택 공급자, 비밀 없는 설정·준비 상태·revision |
| `PATCH /api/settings/ai` | 소유자+CSRF. 사용 가능한 공급자 선택 및 모델 설정 저장, 낙관적 충돌 검사 |
| `PUT /api/settings/ai/gemini-key` | 소유자+CSRF. 새 키 한 번 수신, 안전한 파일 교체, 상태만 반환 |
| `DELETE /api/settings/ai/gemini-key` | 소유자+CSRF. 명시적 삭제, 상태 무효화 |
| `POST /api/settings/ai/{provider}/check` | 소유자+CSRF. 제한된 연결 검사, 생성 시험은 별도 명시적 요청/예산 |
| 일반 화면용 최소 AI 상태 | local session. 활성 표시 이름·사용 가능 여부만 제공하고 민감 진단은 제외 |

설정 화면은 `AI 연결 및 선택 → 자료 보관 → 진단` 순서다. 저장 중 중복 제출·다른 탭 충돌·세션 만료·입력 지우기·선택 불가 이유를 처리한다. 기존 헤더 로그아웃과 사이트 모달, 일반 기능의 키 없는 사용을 유지한다. 모델별 고급 튜닝 UI나 프롬프트 편집기를 새 제품 기능으로 확장하지 않는다.

Ubuntu 설치/doctor는 공급자별 선택적 준비 상태를 보여준다. Claude/Gemini가 미설정이라고 앱 전체 설치 실패로 만들지 않는다. Python·CLI 버전을 잠그고 라이선스 고지를 갱신하되 기존 ML 의존성을 불필요하게 업그레이드하지 않는다. systemd/WSL에서도 같은 config/credential 경로를 사용하고 소스 동기화에 비밀을 포함하지 않는다. 백업 복원은 공급자 설정을 복원할 수 있지만 `인증 준비됨` 캐시는 복원하지 않으며 새 환경에서 재검사한다.

#### 실제 실행과 과잉 검증 방지

- 마스터는 단계별 최소 영향 검사 후 커밋을 고정한다. 검증 위임은 **M3-A: 비밀 저장·설정 API·마이그레이션·제외 정책**, **M3-B: 세 어댑터·모든 호출 경로·작업 전환·웹·운영**의 두 묶음으로 한다. 기존 workflow의 queue·예산·불변 결과·알림 소비 규칙을 그대로 사용한다.
- 기본 회귀는 fake adapter, 가짜 키, 저장된 전사·schema fixture와 mock CLI/HTTP로 한다. 실제 STT/pyannote나 YouTube를 다시 실행해 공급자 선택을 시험하지 않는다. 관련 변경이 없는 M2 모델/획득 증거는 유효 지문을 확인해 재사용한다. 120분 soak는 실행하지 않는다.
- 실제 공급자 확인은 권한과 예산이 확보된 공급자별로 **짧은 가상/공개 전사의 회의록 1회·영상 요약 1회**를 기본으로 잡고 호출/시간/토큰 상한을 별도 기록한다. 승인된 최소 인증/모델 검사와 생성 검사를 구분한다. 구조/취소/오류 조합은 mock으로 검증하며 정상 결과를 얻을 때까지 무제한 실제 호출하지 않는다.
- 새 Gemini 과금, 외부 전송, Claude 설치/로그인 권한이 필요하면 실행 전에 소유자에게 필요한 항목만 묻는다. 키는 앱 설정, 로그인은 공식 CLI에서 소유자가 수행하게 하며 채팅으로 비밀을 요구하지 않는다. 개발 세션의 인증을 가져와 차단을 우회하지 않는다.
- 인증이 없는 공급자는 구현·mock 계약 검증과 실제 실행 상태를 분리해 `LIVE_BLOCKED` 사유를 남긴다. 해당 어댑터를 완전히 검증했다고 쓰거나 UI에서 준비됨으로 만들지 않는다. 나머지 독립 구현을 진행하고 정확한 재개 지점을 남긴다.
- 최종 저비용 전체 회귀는 마스터/검증자 중 한쪽에서 한 번 실행하고 증거를 공유한다. 수정 후에는 실패 항목과 영향 범위만 재검증한다. M3 증거 프로필을 추가할 때 기존 M2의 모든 고비용 실행을 새 필수 조건으로 복제하거나 누락된 `.workflow`를 과거 PASS로 채우지 않는다.

### M3.9 완료·인수인계 및 공식 참고

완료 시 활성 AI 설정·키 입력/교체/삭제·비활성 이유·공급자별 설치/로그인·설정 적용 시점·비밀 제외 범위를 README에 반영한다. 앱은 로컬 개인 사용이며 웹 소유자 키와 외부 AI 인증은 별개임을 유지한다. 공급자별 실제 실행 여부·검증 커밋·미해결 차단·다음 행동은 `.workflow`에 기록한다. 기존 완료 기록을 삭제하지 않고 M3 상태와 실제 구현 계약을 갱신한다. 프로젝트 본문은 한글, 커밋 메시지는 영문, 소스·문서는 LF를 사용한다. 키/토큰이 없는 문서·코드만 원격에 반영한다.

아래 공식 문서를 기준으로 **구현 시 실제 설치 버전·계정에서 다시 확인**한다. 구조화 출력은 의미 정확도 보증이 아니며, SDK/CLI 인증 성공도 무제한 사용량을 보증하지 않는다.

- [Gemini API 키와 서버 측 보관](https://ai.google.dev/gemini-api/docs/api-key), [공식 Python Gen AI SDK](https://googleapis.github.io/python-genai/), [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output).
- [Gemini 서비스 조건](https://ai.google.dev/gemini-api/terms), [프로젝트별 속도·사용량 제한](https://ai.google.dev/gemini-api/docs/rate-limits). 무료 서비스의 민감/기밀정보 제한과 결제 상태별 조건을 구분하고 API 키 교체로 쿼터를 우회하지 않는다.
- [Codex 비대화형 실행](https://developers.openai.com/codex/noninteractive/), [Codex 인증](https://developers.openai.com/codex/auth/). 기존 구독 전용 어댑터의 실행 계약을 보존한다.
- [Claude Code 비대화형 실행](https://code.claude.com/docs/en/headless), [Claude Code 인증](https://code.claude.com/docs/en/authentication). 구독 인증과 `--bare`의 차이, 환경변수 인증 우선순위, JSON 출력과 실행 격리를 확인한다.
