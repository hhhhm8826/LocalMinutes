# 구현 현황과 인수인계

최종 갱신: 2026-09-27

## 현재 상태

MVP G1~G6 구현과 R1/R2/R3 검증을 완료했다. 후속 **M2: 웹 사용성·논제 중심 회의록·영상 요약**을 아래에 등록했다. **M2는 계획 등록 상태이며 아직 구현·검증 완료가 아니다.** 기존 완료 기록은 보존한다. 다음 구현은 M2의 `/goal`과 인수 조건을 기준으로 진행한다.

이 문서는 Git만 받은 사람을 위한 구현 요약과 활성 작업 계획이다. 사용법은 [README](../README.md), 작업·검수 규칙은 [workflow](workflow.md)에 있다. 개인 환경의 `.workflow`는 Git에 포함되지 않으므로 없다고 해서 구현이 누락된 것은 아니며, 과거 실행 증거를 새 환경의 통과 결과로 간주해서도 안 된다.

## 현재 구현의 구조와 계약

아래는 M2 적용 전 구현 기준이다. M2에서 명시적으로 바꾸는 화자 편집·근거 표시·접근권한·자동 생성·보관 정책은 M2 요구를 우선한다. 나머지 안전성·실행 계약은 유지하며, 구현 완료 시 이 절을 실제 동작에 맞게 갱신한다.

- `src/meeting_minutes`가 백엔드·모델·작업 관리자, `apps/web`이 웹 UI, `tests`가 계약/통합 검사, `scripts`가 설치·운영·검증 도구다. 고정 의존성은 `uv.lock`, `apps/web/package-lock.json`, 모델 리비전은 `model_manifest.json`에 있다.
- API는 무거운 모델을 로드하지 않는다. 데이터 디렉터리별 단일 관리자가 작업별 자식을 실행한다. SQLite 원자적 claim과 OS 잠금으로 활성 작업을 하나로 제한한다.
- 입력은 파일 하나당 최대 2,000,000,000바이트·7,200초, 실제 발화자 자동 또는 1~12명이다. 여러 오디오 트랙은 명시적으로 선택한다. 영상은 음성만 사용한다.
- `large-v3-turbo` CPU INT8와 pyannote community-1을 사용한다. 전체 회의 시간축과 화자 ID를 유지하고 정렬 실패는 원문 구간 시각으로 대체한다. 병합 후보는 자동 확정하지 않는다.
- FIFO의 차단된 앞 작업을 몰래 건너뛰지 않는다. 취소는 자식 종료 확인 후 확정한다. PID뿐 아니라 부팅 ID·시작 tick을 확인해 다른 프로세스를 보호한다.
- 완료 산출물은 입력·설정·모델 지문과 파일 해시가 맞아야 재사용한다. 저장 직전 시도 ID·취소·삭제를 확인해 늦은 결과를 차단한다.
- 원본 전사와 확정 회의록은 덮어쓰지 않는다. 수정은 새 버전이며 낙관적 충돌 검사를 한다. 회의록은 시작 시점 전사 snapshot과 실제 근거 ID를 참조한다.
- 외부 텍스트 처리 동의가 없으면 전사까지만 완료한다. Codex는 별도 런타임 인증·작업 디렉터리로 실행하며 개발 지침·도구를 상속하지 않는다. 호출 예약은 재시작해도 유지한다.
- 로그에 원문·인증·임베딩을 남기지 않는다. 삭제는 작업 종료 후 자료를 정리한다. 백업은 인증을 제외하며 복원은 manifest 크기·해시 검사 후 새 경로에만 공개한다.
- 외부 발행은 구현하지 않았다. `minutes.generated`는 검증된 초안 저장, `minutes.approved`는 특정 버전의 사용자 확정이라는 의미 계약만 있다.

## 검증 기준점과 알려진 한계

MVP 최종 문서 체크포인트는 `a3cf51ed5e4e486337122388a9afd148c2a0cac2`, R3 수정 검증 코드는 `ebd08935e1ab20530b6ae07ebeee726027c89457`이다. 이후 변경은 별도 범위 검증으로 관리한다. R1의 동시 트랙 선택, R2의 날짜 표현 근거, R3의 취소 테스트 모델 격리·최종 번들 설치 증거 문제는 모두 수정 확인됐다. 전체 Python 회귀의 통과 77개와 TypeScript·E2E 4개를 보존하고 R3 재검증 4개로 수정 범위를 확인했다.

Ryzen 5800X·WSL 24GiB/8vCPU·앱 4스레드에서 약 3분 한국어/영어 입력은 각각 224.4초/214.0초였다. 과거 120분 반복 음성 시험은 7,497.9초, 관측 최대 RSS 약 3.85GiB, 스왑 0으로 완료했다. **이 기록은 참고용이며 향후 마일스톤·전체 검증의 필수 조건이 아니다. 120분 시험은 사용자 지시 때만 별도로 수행한다.**

자연 12인 회의 정확도·CER/WER/DER는 평가하지 않았다. 혼용·겹친 발화·근거 의미는 사용자 검토가 필요하다. GPU, 실시간 STT, 다중 사용자, 다른 LLM/API 키 폴백, 외부 서비스 발행은 범위 밖이다.

## 활성 마일스톤 M2 — 웹 사용성·논제 중심 회의록·영상 요약

상태: **PLANNED / 구현 시작 전**. 목표는 근거 조각을 수작업으로 조립하는 화면이 아니라, **자동으로 정리된 주요 논제를 읽고 필요한 시작 구간만 들은 뒤 내용을 수정하는 웹**이다. 영상은 같은 전사 기반을 재사용하되 편집 없는 별도 요약본으로 제공한다.

### M2.0 실행할 `/goal`

아래 명령을 기존 **Astra medium 마스터 세션에만** 입력한다. 기존 Sol 5.6 high 세션은 요청받은 검증만 수행한다.

```text
/goal AGENTS.md와 docs/workflow.md를 먼저 읽고 docs/milestone.md의 활성 마일스톤 M2를 W0~W6 및 인수 조건에 따라 구현하라. 기존 MVP와 사용자 자료를 보존하면서 논제 중심 회의록 편집, 문장 단위 전사와 논제 시작 위치, 7일/30일/영구 보관, 설정·진단만 소유자 인증, 자동 인식 업로드, 읽기 전용 영상 요약과 YouTube 링크 입력을 완성하라. 실제 LLM은 기존 Codex CLI만 사용한다. 개발·시험은 Ubuntu/WSL에서 수행하고 Windows 작업 사본을 동기화한다. 기존 Astra medium 마스터와 Sol 5.6 high 검증자 두 세션만 사용하며 검증은 workflow의 codex queue 절차로 커밋과 범위를 고정해 위임하라. 매 작업의 전체 검증, 무제한 모델·CLI·네트워크 재실행, 명시적 사용자 지시 없는 120분 soak를 하지 마라. 완료한 검증 증거는 유효한 범위에서 재사용하고 실제 실행과 mock을 구분하라. 기존 상태·예산·검수 결과를 보존하고 차단 시 독립 작업을 진행한 뒤 정확한 재개 지점을 남겨라. 구현과 인수 검사를 대조하고 README·milestone·필요한 workflow를 동기화한 뒤 실제 완료 항목과 미완료·외부 차단을 보고하라. 기능이나 검사를 누락시키고 완료로 처리하지 마라. 이 goal은 새 원격 push·공개 배포나 별도 유료 서비스 사용 승인을 포함하지 않는다.
```

### M2.1 범위와 우선 결정

- 기존 React/FastAPI/SQLite/로컬 파일/단일 워커를 유지한다. 개발·검증은 Ubuntu/WSL, 배포 대상은 Ubuntu 24.04 LTS x86_64다. Windows 네이티브 ML 지원을 추가하지 않는다.
- 실제 생성기는 개인 구독 **Codex CLI 하나**다. 사용자 문구와 작업 종류만 공급자 중립적으로 만들고 Gemini·다른 API·로컬 LLM·소셜 로그인·외부 발행은 구현하지 않는다. 미래 공급자 확장을 이유로 거대한 플러그인 체계를 만들지 않는다.
- 화자 수 상한 12명, 입력 120분·2,000,000,000바이트, CPU INT8·pyannote community-1, 전체 원본 시간축, 작업 하나씩 FIFO, 취소·재시도·복구는 유지한다. 최대 지원 길이는 장시간 시험의 실행 승인이 아니다.
- 화면에서 사용자가 직접 화자 실명 식별·이름 변경·배정 변경·병합을 하는 흐름은 제거한다. 회의 내 자동 구분의 일관성을 목표로 하며 회의 간 인물 식별·생체정보 사전 등록은 하지 않는다.
- 새 웹 입력은 언어·화자 수 자동, 연결된 AI를 통한 결과 생성 항상 활성이다. 과거의 전사 전용 자료를 업데이트만으로 외부 전송하거나 유료 폴백하지 않는다.
- 회의록은 읽기 중심으로 보여주고 필요할 때 논제와 본문을 편집한다. 영상 요약은 읽기 전용이다. 두 종류는 목록·생성 스키마·프롬프트를 구분하되 대기열·저장·음성 처리 코드를 복제하지 않는다.

### M2.3 문장 단위 전사와 자동 화자 일관성

**원본 전사/정렬 → 읽기용 발언 단위 → 논제와 시작 위치**의 세 계층을 둔다.

1. 기존 단어 ID·시각·원문 snapshot은 불변으로 보존한다. 파생 `utterance`에는 ID, `start_ms`, `end_ms`, 읽을 수 있는 `text`, 자동 화자 ID, 구성 원본 ID, 불확실성 정보를 둔다. 파생 규칙 버전과 입력 전사 버전을 기록한다.
2. 원본 ASR의 문장·공백·구두점, 실제 화자 전환, 침묵·겹침과 적절한 길이 경계를 함께 사용해 발언을 묶는다. 한국어·영어의 공백을 망가뜨리거나 발언을 누락·중복시키지 않는다. 단순 고정 단어 수로 문장을 자르지 않는다.
3. 단어가 짧다는 이유만으로 발언 전체를 짧은 화자 샘플로 판단하지 않는다. 단어별 `150ms` 판정과 발언 수준의 신뢰 판단을 구분한다. 혼용·정렬 실패는 기존 원문 구간 시각으로 대체한다.
4. 전체 회의 기준 pyannote 구분을 유지하고 표시 번호는 회의 안에서 안정적으로 부여한다. 짧은 맞장구·화자 경계 흔들림은 충분한 주변 근거가 있을 때만 보정한다. 겹친 두 화자를 병합하거나 이름·발언 뜻으로 같은 사람을 추정하지 않는다. 불확실하면 미확정 상태를 유지한다.
5. 기존 임베딩·regular/exclusive 결과로 오분리 사례를 먼저 확인한다. 임의 유사도 기준으로 화자를 무조건 합치거나 별도 Whisper 세그먼트 임베딩 엔진을 다시 만들지 않는다. 자동 보정은 고정 평가 세트에서 원본 대비 개선·비회귀를 확인한 것만 기본 적용한다. 성능 개선이 확인되지 않으면 원본 방식을 유지하고 한계를 기록한다.
6. 화자 수정·병합 UI와 정상 사용자 흐름의 화자 변경 명령은 없앤다. 기존 사용자 수정 버전·화자 이름은 과거 자료 열람을 위해 보존하며 자동 재처리로 덮어쓰지 않는다. 전사 텍스트 교정은 보조 영역에서 문장·발언 단위로 제공하고 새 버전으로 저장한다.
7. 이미 저장된 단어 전사는 모델 재실행 없이 파생 읽기 뷰를 만들 수 있게 한다. 단, 존재하지 않는 텍스트·시각을 보충하지 않는다. 파생 규칙 변경 시 관련 캐시만 무효화하고 STT·pyannote를 불필요하게 다시 실행하지 않는다.

### M2.4 논제 중심 회의록 생성·수정

#### 결과와 화면

기본 상세 화면 순서는 **회의 개요·요약 → 주요 논제 → 사용자가 보완할 결정·할 일 → 접힌 전사문**이다. 기본 상태에서는 읽기 좋은 문서로 보여주고 편집을 선택했을 때 입력란을 연다.

- 논제에는 제목, 논의 요약, 합의·제안·보류 등 현재 결론의 요지와 관련 시작 위치 1~n개를 담는다. 같은 논제가 뒤에 재등장하면 하나의 논제로 묶되 떨어진 시작 위치를 보존한다.
- 시간 버튼은 `03:12 논의 시작`, `18:40 재논의`처럼 표시한다. 내부 근거 ID 목록이나 단어 버튼을 기본 화면에 나열하지 않는다. 필요 시 보여주는 발췌도 문장과 주변 맥락이어야 한다.
- 시작 위치는 모델이 임의 숫자로 만들지 않는다. 모델은 유효한 발언 ID·구간을 선택하고 서버가 원본 시각으로 변환·정렬·중복 제거한다. 연속된 동일 구간은 합치고 논제와 무관한 앞선 발언을 시작점으로 잡지 않는다.
- 논제 위치를 누르면 같은 화면의 재생기로 이동해 해당 위치부터 들을 수 있게 한다. 편집 중인 입력·스크롤·선택 상태를 불필요하게 초기화하지 않는다. 1시간 이상은 `HH:MM:SS` 형식을 지원한다.
- 논제 제목·내용의 수정, 추가·삭제·순서 변경, 전체 요약 수정, 결정·할 일 직접 입력, 변경 취소·저장, 새 버전·확정을 제공한다. 저장하지 않은 변경 경고와 낙관적 충돌 검사는 유지한다. 재생성은 새 초안이며 수동 입력·확정본을 자동 덮어쓰지 않는다.
- 개별 근거를 모두 확인하거나 항목마다 `verified`로 바꾸는 것을 저장·문서 확정의 선행 조건으로 삼지 않는다. 확정은 사용자의 문서 단위 행동이지 AI 정확도 보증이 아니다.
- 상세 결정, 담당자, 기한은 사용자가 보완하기 쉽게 둔다. 담당자는 화자 드롭다운에 종속시키지 않고 직접 입력할 수 있게 한다. 수동 항목은 자동으로 `user_authored` 등 출처를 구분하고 근거 없는 사용자 입력을 거부하지 않는다. 이를 위해 사용자가 먼저 검토 상태를 수동 전환할 필요가 없어야 한다.
- 안내는 결정·할 일 편집 영역에 짧게 한 번만 둔다: `자동 정리된 내용입니다. 구체적인 결정·담당자·기한은 직접 확인하고 보완하세요.` 업로드 화면에 삭제 요청한 안내 문구를 다시 추가하지 않는다.

#### 논제·결정·미결의 판단 규칙

- 전체 흐름에서 실제 주요 안건을 추출한다. 단순 질문 모음이나 모든 발언의 압축본을 만들지 않는다. 안건과 무관한 잡담·농담·수사적 질문·이미 해결된 질문은 미결로 남기지 않는다.
- 예: 농담으로 나온 `그럼 우리 다 퇴사할까요?`는 미결 질문이 아니다. `보안 검토가 끝나지 않아 다음 회의에서 배포 여부를 정하자`는 실제 후속 확인 사항이다. 질문부호나 특정 단어만으로 판정하지 않고 전후 맥락·응답·후속 합의를 함께 본다.
- 명시적 합의와 제안·추측·보류를 구분한다. 회의 후반의 번복·취소를 반영하고, 불확실한 농담을 실행 항목이나 확정 결정으로 승격하지 않는다. 근거가 부족한 미결 목록은 비어 있어도 된다.
- 자동 생성은 주요 논의와 결정 요지에 집중한다. 발언에 없는 실행 세부사항·담당자·날짜를 만들지 않는다. 명시된 내용도 자동 정리 초안이라는 출처를 유지한다.
- 긴 입력은 기존 문맥·호출 예산 안에서 발언·논제 경계를 고려해 분할한다. 청크 경계의 문맥과 뒤늦은 해결·번복을 통합하고 짧은 요약을 반복 재요약하며 맥락을 잃지 않는다. LLM 호출 단계 수를 늘리는 방식부터 택하지 않는다.
- 프롬프트 버전, 결과 스키마, 문서 종류, 파생 전사 규칙을 생성 식별자·캐시 지문에 반영한다. 기존 분할·통합·로컬 검증·schema 출력 모두 함께 수정한다. 프롬프트만 바꾸거나 JSON 형식 통과를 의미 정확도 통과로 간주하지 않는다.

#### 결과 계약과 과거 버전

결과는 버전 있는 구조화 JSON을 정본으로 둔다. 회의록의 `topics`에 논제별 시작 위치를 저장하고, 결과 자체에 제목·시각·문서 종류·생성 정보 등 열람에 필요한 최소 정보를 갖춘다. 원본 ID는 내부 추적용으로 남기되 UI의 필수 편집 단위로 쓰지 않는다.

기존 schema 1과 사용자 편집본은 읽기 호환을 제공한다. 필요한 변환은 새 버전 또는 읽기 어댑터로 하며, 모든 과거 회의의 LLM 재생성을 마이그레이션에 넣지 않는다. 전사가 남아 있는 이전 결과는 기존 근거를 읽을 수 있는 문장·시작 위치로 연결한다. 전사가 없어 복원할 수 없는 위치는 확인 불가로 남긴다.

### M2.5 자료 보관 기본값과 만료 후 동작

| 보관 대상 | 새 기본값 | 정책 |
|---|---|---|
| 업로드 원본 음성·영상 + 재생용 추출 음성 + YouTube에서 받은 음성 | **통합 7일** | 설정 항목은 하나다. 별도 original/audio 일수 입력을 없앤다. |
| 전사 원본·편집본·읽기용 파생 전사, 정렬·화자 결과·임베딩, 전사 포함 임시 프롬프트·체크포인트 | **30일** | 같은 내용을 복제한 JSON·임시 결과·검색 데이터도 포함한다. |
| 회의록·영상 요약본과 그 보존 버전 | **영구** | 자동 만료 대상에서 제외한다. 사용자의 전체 삭제는 별개다. |
| 자동 삭제 사용 | **기본 켜짐** | 실제 정리 작업까지 활성화한다. UI 체크만 바꾸지 않는다. |

- 통합 `media_days`, `transcript_days`, `enabled` 계약과 DB 마이그레이션을 마련한다. 결과 문서에는 자동 삭제 일수를 적용하지 않는다. 백엔드 기본값·DB 초기값·설정 폼·문구·시험을 일치시킨다.
- 신규 자료의 보관 기산점은 실제 입력 수신 완료 시각으로 고정한다. 회의가 열린 과거 날짜나 YouTube 게시일을 사용하지 않는다. 원본과 추출 음성은 같은 만료일을 쓰며 조회·수정·재생성·재시도로 수명이 계속 연장되지 않는다. 처리 중인 자료는 실행 상태·잠금 확인 후 종료될 때 정리한다.
- 기존 설치의 변경하지 않은 초기 정책은 7/30/영구·자동 삭제 켜짐으로 이전한다. 사용자가 명시적으로 바꾼 값은 보존한다. 예전 원본/음성 값이 다르면 더 긴 보관값으로 통합하고 무기한 값이 있으면 무기한을 보존해 갑작스러운 삭제를 피한다. 기존 자료에 새 유한 정책을 처음 적용할 때는 마이그레이션 시각부터 해당 기간을 부여하는 일회성 유예를 기록한다. 구분이 불가능한 정책을 임의로 사용자 변경 전 값이라고 단정하지 않는다.
- 전사 30일 만료는 `minutes_revisions`나 요약본을 삭제하지 않는다. DB 참조·목록 검색·내보내기·현재 버전·편집/확정 경로를 함께 분리한다. 내부 전사 참조에는 만료 상태를 표현하고 마이그레이션 후 외래키 무결성을 확인한다.
- 7일 후에는 재생 버튼만 사용할 수 없다고 표시하고 회의록 편집은 계속된다. 30일 후에는 전사 보기·원문 근거 확인·원문 기반 재생성만 제한한다. 결과 본문과 이미 계산한 논제 시작 시각은 유지한다. 원본 없는 상태에서 새 자동 근거나 시각을 만들어내지 않는다.
- 만료된 원본을 읽다가 상세 화면 전체가 오류로 바뀌면 안 된다. 가용 상태를 API로 명확히 반환하고 웹의 전사/회의록 로딩을 독립시킨다. 수동 추가 항목에는 원문 링크가 없어도 된다.
- 임베딩은 `diarization`·원본 전사 snapshot 등 중복 저장 위치까지 제거한다. 요약본에 전사 전체나 임베딩을 숨겨 영구 보관하지 않는다. 기존 저장된 회의록 본문 자체는 사용자 문서로 보존한다.
- 전체 삭제는 기존처럼 원본·파생물·전사·결과·검색 정보까지 정리한다. 실행/재시도/삭제/정리 경쟁과 늦은 결과 저장 방지를 유지한다. 자동 만료는 실행 중 작업을 임의 취소하지 않는다.
- 백업에서 복원할 때 만료 상태와 정책을 유지한다. 외부로 내보낸 파일이나 기존 오프라인 백업까지 자동 삭제했다고 주장하지 말고 운영 안내에서 범위를 구분한다.

### M2.6 키 없는 일반 사용, 설정·진단 보호

여기서 키는 현재 웹의 **소유자 키**다. 웹 소유자 인증과 서버의 Codex 구독 로그인을 혼동하지 않는다. 소유자 키 없이 웹을 사용하더라도 AI 생성에는 연결된 Codex 런타임 로그인이 필요하다.

| 기능 | 소유자 키 없는 로컬 사용자 | 소유자 인증 후 |
|---|---|---|
| 내 회의·영상 요약 목록/상세/업로드/URL 입력/작업 상태/취소/재시도 | 허용 | 허용 |
| 회의록 편집·확정·재생성·내보내기·일반 자료 삭제 | 허용 | 허용 |
| 설정 조회·변경, 진단 조회·실행, 환경 경로·연결 상세·사용량 진단 | 불허 | 허용 |

- 앱 진입을 로그인 화면으로 막지 않는다. 키 입력 없이 같은 출처의 로컬 사용자 세션과 CSRF 토큰을 초기화하고, 설정·진단 진입에서만 소유자 인증을 요구한다. 최소 권한/기능 정보 외에 민감한 진단·설정 값을 일반 화면에 내려주지 않는다.
- 프런트엔드 탭 숨김만으로 구현하지 않는다. API 권한 경계를 분리하고 직접 요청해도 설정·진단이 보호되게 한다. 소셜 로그인을 나중에 연결할 수 있도록 현재 세션의 권한 확인을 한 경계에 모은다. 다중 사용자·계정별 데이터 분리는 이번 범위가 아니다.
- 루프백 바인딩, Host/Origin 검증, CSRF, SameSite/HttpOnly 쿠키, 요청 크기 제한, 안전한 파일 접근을 유지한다. 익명 사용을 위해 CORS `*`, `0.0.0.0`, CSRF 비활성화를 도입하지 않는다. 키 없는 접근은 외부 공개 서비스 모드가 아니다.
- 설정 및 진단 화면에서는 **설정이 위, 진단이 아래**다. `로그아웃`은 우상단 `LOCAL · CPU` 옆에 소유자 인증 상태일 때만 표시한다. 미인증 상태에는 필요 시 설정 로그인 진입만 제공한다.
- 로그아웃은 소유자 권한·민감 캐시를 제거하고 일반 로컬 사용자 상태로 돌아온다. 회의/요약 사용을 막거나 처리 중 워커를 중단하지 않는다. 세션 만료·로그아웃·다른 탭 변화 후에도 설정 API가 열려 있으면 안 된다. 저장하지 않은 편집 처리도 명확히 한다.

### M2.7 새 회의 입력

- `언어`, `실제 발화자 수` 입력을 제거한다. 새 웹 요청은 `language=auto`, `speakers=null`로 보내며 백엔드도 신규 일반 흐름의 자동값을 보장한다. pyannote 자동 범위는 1~12명이다. 기존 데이터의 수동 설정은 과거 실행 기록으로 보존한다.
- 회의 일시는 폼을 새로 열 때 **Asia/Seoul의 현재 날짜·시간**을 미리 입력한다. 사용자는 실제 회의 일시로 수정할 수 있다. 브라우저·서버 시간대가 UTC나 미국이어도 같은 한국 시각을 표시한다. 입력을 `+09:00`의 시각으로 해석해 저장하고 `timezone=Asia/Seoul`을 명시한다. `toISOString().slice()` 또는 브라우저 로컬 `new Date(datetime-local)`에 그대로 의존하지 않는다.
- 기존 옵션은 **`연결된 AI를 사용한 회의록 생성`**으로 바꾸고 항상 켜진 고정 상태로 표시한다. 켜지 않은 기본값·업로드별 재동의·전사 전용 선택은 새 업로드 흐름에서 제거한다. 해당 옵션 아래 기존 Codex/동의 안내 문단을 삭제한다. 상세의 새 초안 생성에도 같은 문구 정책을 적용한다.
- 서버에는 사용자가 이번 생성 요청에서 활성화된 AI 처리를 요청했다는 상태를 저장한다. 기존 `allow_external_text=false` 자료를 읽기만 했는데 자동 전송하지 않는다. 연결 실패·사용량 제한은 명확한 작업 상태로 보여주고 무료/유료 다른 공급자로 자동 전환하지 않는다. 장애 시 전사만 보존하고 작업을 끝내는 기존 복구 기능은 남긴다.
- `새 회의 업로드`는 별도 페이지 상태/라우트로 전환한다. 입력 중에는 기존 목록·선택 상세·검색 폼을 아래에 렌더링하지 않는다. 닫기/뒤로 가기로 이전 목록·필터·선택 상태를 복원하고, 업로드 성공 시 생성한 자료 또는 해당 대기열 위치를 명확히 보여준다. 뒤로 가기·새로고침·전송 실패 재시도에서도 중복 자료가 생기지 않게 한다.
- 여러 오디오 트랙의 명시적 선택, 크기/길이 검사, 진행률, 업로드 멱등성은 유지한다. 새 요약 입력에도 화면 분리·자동 인식·항상 켜진 AI 생성 원칙을 재사용한다.

### M2.8 영상 요약 탭과 YouTube 입력

#### 제품·출력

주 메뉴에 **`영상 요약`**을 추가한다. 회의 목록과 별도 목록·입력·상세를 제공하며 입력은 **파일 업로드 / YouTube 링크** 중 하나다. 회의와 동일한 음성 추출·전사를 사용하고 화면·슬라이드·자막 이미지 분석은 하지 않는다.

- 결과 이름은 UI·작업 단계·내보내기에서 **`요약본`**이다. 회의록의 결정·할 일·담당자·미결 질문 틀을 그대로 재사용하지 않는다.
- 시사·경제 영상에 맞게 전체 핵심 요약, 주제별 설명, 영상에서 실제 언급한 주요 수치·시점·주장·전망을 정리한다. 없는 항목은 억지로 채우지 않는다. 다른 종류의 대화 영상도 일반 주제 요약으로 처리한다.
- 설명자의 주장·의견·예측은 그 출처를 드러내고 확정된 사실과 구분한다. 숫자는 단위·대상·기준 기간을 보존한다. 정치적 지지·우열 판단이나 매매 권유를 생성하지 않고, 요약기가 별도로 최신 사실을 검증한 것처럼 쓰지 않는다. 외부 뉴스 검색·금융 데이터 조회는 이번 작업에 넣지 않는다.
- 영상 제목·채널·게시일과 분석 시각을 구분한다. 게시일을 모르면 미상으로 두고 업로드 일시를 발언의 기준 날짜로 임의 대체하지 않는다. `오늘/내년`이 불명확하면 원표현을 유지한다.
- 주제별 **시작 시간만** 간결하게 보여준다. 단어 근거·개별 검토 상태·화자 수정·본문 편집·확정 버튼은 없다. 서버에서도 요약본에 회의록 편집/확정 API를 적용할 수 없게 한다. 생성 실패 재시도와 명시적 새 요약 생성은 별개 기능이며 새 버전으로 저장할 수 있다.
- 파일은 로컬 음성의 해당 시간, YouTube는 로컬 음성 또는 원본 영상의 시간 링크로 이동한다. 로컬 음성이 만료돼도 제목·요약·시간은 남고 YouTube 원본 시간 링크는 사용할 수 있다. 별도 iframe 삽입을 위해 기존 CSP를 완화하지 않는다.
- 문서 종류와 입력 종류를 분리한다: 예를 들어 `document_kind=meeting|video_summary`, `source_kind=file|youtube`. 기존 자료는 `meeting/file`로 호환한다. 기존 테이블을 모두 이름 바꾸기보다 작은 확장과 종류별 스키마/렌더러를 사용한다. 원본 획득·전사·큐·삭제·보관·내보내기 기반은 공유한다.
- 두 탭의 자료는 목록에서 구분하되 **전역 FIFO는 하나**다. 다른 탭의 작업 때문에 대기하는 경우에도 현재 실행 작업과 실제 전체 순번을 알 수 있게 표시한다. 영상 다운로드 역시 같은 실행 슬롯에서 수행하고 별도 병렬 다운로드 큐를 만들지 않는다.

#### YouTube 획득과 안전 경계

- 기본 획득기는 `yt-dlp` 어댑터다. URL 제출은 빠르게 자료·작업을 등록하고, 워커가 정보 확인 → 음성 다운로드 → 기존 파이프라인으로 진행한다. `SOURCE_CHECK`/`DOWNLOAD` 등의 단계와 오류를 UI에 표시한다. 웹 요청 안에서 긴 다운로드를 끝낼 때까지 기다리지 않는다.
- 지원 입력은 HTTPS의 `youtube.com/watch?v=...`, `youtu.be/...`, `/shorts/...`, `/live/...`의 **단일 영상**이다. 허용 호스트·유효 영상 ID를 파싱해 정규 URL로 다시 만든다. 허용하지 않은 하위 도메인·사용자 정보·비표준 포트·위조 호스트·IP 주소·임의 사이트는 거절한다. `list`, `si`, `t`, `start` 등은 처리 대상 확장이나 시작 오프셋으로 사용하지 않고 전체 영상 기준으로 정규화한다.
- 채널·재생목록 일괄 처리, 진행 중/예정 라이브, 유료/멤버십/로그인 필요/DRM 보호 영상은 지원하지 않는다. 종료된 라이브는 길이와 접근 조건이 확인되면 일반 단일 영상으로 처리한다. 삭제·지역/연령/봇 제한 등 접근 실패는 이유와 파일 업로드 대안을 표시하고 우회하지 않는다.
- 음성 트랙만 받으며 영상 프레임·썸네일·댓글·자막을 요약 입력으로 대신 사용하지 않는다. 제목·설명만 확보하고 전사에 성공한 것처럼 요약하지 않는다. 오디오가 없거나 길이를 안전하게 확인할 수 없으면 명시적으로 중단한다.
- 길이 7,200초·수신 파일 2,000,000,000바이트 제한은 정보 확인과 수신 과정 및 `ffprobe` 검사에 모두 적용한다. 파일 크기 메타데이터가 없을 때도 누적 수신량·디스크 사용량을 제한한다. 초과 영상을 조용히 2시간으로 잘라 전체 요약처럼 내보내지 않는다.
- 재시도/조각 수/전체 소요시간을 유한하게 제한한다. 다운로드 중 취소·서버 재시작·삭제는 기존 프로세스 그룹과 실행 fencing을 사용하며 임시 파일을 정리한다. 수신 완료·해시 확인 전에는 정상 원본으로 공개하지 않는다. 동작 중인 JS 런타임·FFmpeg도 취소 대상이다.
- URL 허용 목록만으로 SSRF 방어가 끝났다고 보지 않는다. 추출 결과·리디렉션·DNS가 향하는 사설/루프백/link-local/메타데이터 주소 접근을 차단하고, 필요한 YouTube/CDN 요청만 허용하는 획득 경계를 검증한다. generic extractor·임의 URL 폴백은 없다. ASR 워커의 오프라인 모델 정책은 유지한다.
- 다운로더는 고정 인자 배열로 호출하고 사용자 URL·제목을 셸·출력 경로·명령으로 결합하지 않는다. 서버 생성 파일명, 독립된 임시 디렉터리, 제한된 환경을 사용한다. 개인 yt-dlp 설정·플러그인·브라우저 쿠키·인증·프록시를 자동 상속하지 않는다. 필요한 통신과 무관한 로컬 파일 접근도 제한한다.
- 버전을 잠그고 YouTube 지원에 필요한 `yt-dlp-ejs`와 지원 JS 런타임을 Ubuntu 설치·진단·릴리즈에 포함한다. 런타임은 지원 버전을 확인한 Deno 하나로 정해 경로/버전을 기록한다. 처리 도중 자동 업데이트·원격 구성요소 설치를 하지 않는다. 라이선스 고지도 갱신한다.
- 재사용·처리가 허용된 영상만 다루도록 사용 범위를 문서화한다. 공개 URL이라는 이유만으로 다운로드·재배포 권한을 보장하지 않는다. 테스트 자료는 권한과 원본 주소·선택 구간을 기록하고 원본 미디어를 Git에 넣지 않는다.
- 콘텐츠 제목·전사·외부 메타데이터는 전부 비신뢰 데이터다. Codex에게 다운로드·웹 검색·셸 실행 권한을 주지 않고 기존 텍스트 전용 생성 격리를 유지한다.

| 미인증/소유자/로그아웃/세션 만료·직접 API | 일반 작업은 가능하고 설정·진단은 보호. CSRF·Origin·Host·파일 경계는 그대로. |
| UTC·미국 브라우저에서 새 회의 열기 | 현재 KST 표시·정확한 UTC/+09:00 저장, 언어/화자 입력 없음, AI 생성 고정 활성, 배경 목록 없음. |

#### 실제 품질 확인과 검증 예산

- 먼저 고정된 전사·화자·시각 fixture와 mock 생성기로 구조/보안/웹을 시험한다. 실제 품질 평가는 수동으로 논제·농담/미결·시작 허용 구간을 표시한 짧은 자료로 별도 수행한다. mock이나 문자열 규칙 시험만으로 AI의 의미 판단을 검증했다고 하지 않는다.
- 기존 허가된 3분 내외 한국어·영어 자료와 출력이 있으면 우선 재사용한다. 실제 모델은 관련 화자/정렬 경로를 바꾼 경우에만 필요한 짧은 자료를 다시 실행한다. 자연 12인 회의 정확도 개선을 측정하지 않았으면 그렇게 보고한다.
- 실제 Codex 확인은 교정된 전사로 회의록/영상 요약을 각각 확인하고, 같은 전사를 사용해 프롬프트 변경 전후를 비교한다. 전체 전사를 다시 돌려 호출을 시험하지 않는다. 호출 횟수·시간·입력 해시의 명시적 예산 안에서만 실행한다.
- YouTube 실제 연결은 재사용 권한을 확인한 3분 내외 단일 영상 하나로 정보 확인·음성 획득·시간 매핑을 점검한다. 나머지 제한/실패는 fixture로 검사한다. 새 라이브 네트워크 실행 예산과 의존성 준비를 먼저 기록하며 차단을 만났다고 URL을 무작위로 바꾸거나 쿠키를 가져와 반복 시도하지 않는다.
- 기존 예산·로그인·자료 권한으로 수행할 수 없는 실제 검사는 `BLOCKED`로 남긴다. 가능한 오프라인 구현을 진행하되 실제 YouTube/모델/CLI 성공이나 M2 전체 완료를 만들어내지 않는다. 프롬프트 변경 후 관련 없는 옛 CLI PASS를 새 품질 증거로 사용하지 않는다.
- **검증 위임은 기본 두 묶음**이다. `M2-A`: W1~W3의 전사/결과 버전/보관/편집 계약. `M2-B`: W4~W6의 인증/입력/YouTube/웹 통합과 최종 증거. 요청 ID는 기존 ID와 중복되지 않게 만들고 workflow의 고정 커밋·범위·명령·예산·알림 소비를 따른다.
- 마스터는 작업마다 영향 범위의 최소 검사를 한다. 최종 저비용 전체 회귀는 마스터 또는 검증자 한쪽에서 한 번 실행하고 다른 쪽은 같은 증거를 검토한다. `release`에 포함되는 검사를 별도 전체 실행으로 연이어 중복시키지 않는다. 수정 후에는 실패 항목·관련 범위만 재검증한다.
- 120분 soak, 반복 전체 모델 실행, 여러 검증 세션, 검증자 재귀 위임은 포함하지 않는다. 정상 완료 알림에 답장하지 않고 기존 소비 도구를 사용한다. `.workflow` 증거가 없는 새 환경은 과거 통과 이력을 재창작하지 않는다.

### M2.10 완료·인수인계

M2의 완료는 체크박스뿐 아니라 구현 결과·범위 검증·실제 실행 증거·외부 차단 상태를 대조해 판단한다. 미완료 기능을 범위 밖으로 바꾸거나 필수 검사를 삭제해서 끝내지 않는다. 사용자 데이터에 파괴적 시험을 하지 않는다.

완료 시 이 문서의 현재 상태/구현 계약/완료 표를 실제로 갱신하고 활성 작업은 정리한다. README에는 키 없는 로컬 사용의 범위, 설정/진단 로그인, 연결된 AI의 실제 Codex 인증, 자료 보관과 만료 후 제한, YouTube 지원/제한·의존성, Ubuntu/Windows 실행법을 반영한다. 작업 규약이 바뀌지 않았다면 workflow는 불필요하게 고치지 않는다. 상세 증거·차단·재개점은 `.workflow`에 둔다.

설계 참고: [Codex 명령 및 파일 기반 goal](https://developers.openai.com/codex/cli/reference/), [yt-dlp 공식 의존성·옵션](https://github.com/yt-dlp/yt-dlp#dependencies), [OWASP SSRF 방어](https://cheatsheetseries.owasp.org/cheatsheets/Server_Side_Request_Forgery_Prevention_Cheat_Sheet.html). 설치 시 버전과 실제 지원 조건은 해당 공식 문서로 다시 확인한다.

## 다음 작업의 기록 방법

새 작업을 시작하면 이 문서에 목표·범위·상태·남은 작업을 짧게 추가한다. 완료 시 실제 기능·영향 경로·검증 근거를 완료 표에 반영하고 진행 항목을 정리한다. 상세 변경 사유나 대화 이력은 쌓지 않는다. `.workflow/state.json`에는 체크포인트·진행 작업·다음 행동·미완료 리뷰·문서 동기화 상태를 남긴다.
