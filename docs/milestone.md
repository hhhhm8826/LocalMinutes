## 현재 구현의 유지 계약

M3 적용 전 기준이다. 기존 Codex 전용 경계의 확장은 M3를 따르며, 아래 동작을 이전 MVP 상태로 되돌리지 않는다.

- **환경·구조:** Ubuntu/WSL에서 실행하고 Ubuntu 24.04 LTS x86_64로 제공한다. `src/meeting_minutes`는 백엔드/작업 관리자, `apps/web`은 웹, `tests`·`scripts`는 검사/운영이다. 의존성은 `uv.lock`·`apps/web/package-lock.json`, 모델 리비전은 `model_manifest.json`으로 고정한다. API는 모델을 로드하지 않는다.
- **입력·음성:** 최대 2,000,000,000바이트·7,200초, 언어/화자 자동·화자 상한 12명이다. 여러 오디오 트랙은 명시적으로 선택한다. `large-v3-turbo` CPU INT8·pyannote community-1, 전체 원본 시간축·화자 ID와 단어 원본을 유지하며 정렬 실패는 원문 구간 시각으로 대체한다. 근거 없는 자동 화자 병합은 하지 않는다.
- **처리:** 분석 FIFO와 텍스트 전용 AI 재생성 FIFO가 독립적으로 각각 한 건씩 실행된다. lane 안의 차단된 앞 작업을 몰래 건너뛰지 않는다. 재생성은 저장된 전사를 사용하며 음성을 다시 분석하지 않는다. 원자적 claim·OS 잠금·프로세스 식별을 유지한다.
- **복구·버전:** 입력/설정/모델 지문·파일 해시가 맞는 완료 단계만 재사용한다. 저장 전 attempt·취소·삭제를 검사하고 취소는 자식 종료 확인 후 확정한다. 원본 전사·과거 결과·사용자 수정본은 덮어쓰지 않고 낙관적 충돌 검사를 한다. 재생성 결과는 새 기본 버전이지만 생성 중 별도 수정/새 전사가 있으면 이를 덮어쓰지 않는다. 편집 중이 아닐 때만 최신 결과를 자동 반영한다.
- **접근·입력 화면:** 일반 목록/입력/편집은 키 없이 사용하며 설정·진단만 소유자 인증을 요구한다. 루프백·Host/Origin·CSRF 보호를 유지한다. 설정은 진단 위, 로그아웃은 헤더에 둔다. 새 입력에서는 기존 목록/상세를 숨기고 일시는 현재 KST로 시작한다. AI 생성은 항상 활성이고, 제목 없는 파일은 같은 요약 응답에서 AI 제목을 얻으며 YouTube는 원본 제목을 사용한다.
- **회의록:** 논제 제목·본문과 시작/재논의 재생을 중심으로 읽고 수정한다. 제목은 2~6단어의 명사구·최대 60자로 생성하며 과거 제목을 본문 발췌로 꾸미지 않는다. 재논의는 다른 논제를 거쳐 돌아온 경우에만 구분한다. 개별 근거 검증을 저장의 필수 조건으로 삼지 않는다. 화자 편집·전사 열람/교정 패널·최종 확정 버튼은 제공하지 않으며 기존 데이터/호환 API는 보존한다.
- **영상·공통 화면:** 영상 요약은 편집/버전 선택 없이 최신 결과를 보여주되 내부 이력은 남긴다. 수치·단위·기간·주장 주체는 주제 본문에 통합하고 별도 주장 목록은 표시하지 않는다. 재생기는 요약 위, 생성/텍스트/Markdown 내보내기는 생성 박스에 둔다. YouTube 원본 링크는 전체에 하나다. 확인은 사이트 모달, 탭 닫기/새로고침의 미저장 보호는 브라우저 경고를 쓴다. 뒤로가기는 우상단, 입력 시작 버튼은 오른쪽, 목록에는 해당 처리/대기 상태를 표시한다.
- **YouTube:** 허용된 단일 영상 전체의 음성만 획득한다. 로그인/쿠키·진행 중 라이브·재생목록·DRM·직접 HTTPS 음성 형식이 없는 자료는 지원하지 않는다. 고정 yt-dlp/EJS/Deno·bubblewrap·제한된 HTTPS 경계를 유지하고 실패/부분 음성을 전체 성공으로 저장하지 않는다. 자료 제한·취소·임시 파일 정리는 파일 입력과 같은 기준을 적용한다.
- **보관·외부 전송:** 자동 삭제 기본값은 미디어 7일·전사/정렬/임베딩 30일·결과 영구다. 수신 완료일부터 계산하며 기존 정책/일회성 유예를 보존한다. 원문 만료 뒤에도 결과 편집/열람/내보내기는 가능하고 원문 기반 재생성은 제한된다. 로그/백업에는 인증을 포함하지 않으며 전체 삭제는 파생물까지 정리한다. 현재 Codex는 전용 런타임에서 허용된 텍스트만 처리하고 개발 지침/도구를 상속하지 않는다. 과거 전사 전용 자료는 열람/업데이트만으로 전송하지 않는다. 외부 발행은 이벤트 의미 계약만 있고 구현하지 않았다.
- **내보내기:** 회의록은 선택 버전, 영상은 화면의 최신 결과와 일치시킨다. 파일명은 `minutes_verNN_MMDD` / `summary_verNN_MMDD`와 `.md/.txt`, 날짜는 결과 저장일 KST다. 최초 회의록 버전은 `초안`, 이후 `버전02_0927` 형식이다. 다운로드는 UTF-8·CRLF이며 재생 시작 시각을 제외한다. 의미 있는 날짜/수치·특수문자를 보존하고 Markdown만 필요한 이스케이프를 적용한다. 읽기/내보내기의 문장 줄바꿈은 소수점·URL·약어·문단을 보존하며 저장 원문/편집 입력/제목은 바꾸지 않는다. 저장소 소스·문서는 LF다.

### M3.2 Gemini 키 저장과 비밀 경계

#### 저장 위치와 교체

기본 위치는 **`<config_dir>/.apikey/gemini.json`**, 기본 설정 경로를 쓰면 **`~/.config/local-meeting-minutes/.apikey/gemini.json`**이다. `MINUTES_CONFIG_DIR` 변경도 따른다. `.apikey`를 실행 CWD나 Windows 저장소에 만들지 않으며 정적 웹·업로드·산출물 디렉터리 밖에 둔다.

- 현재 키 하나만 저장한다. 같은 고정 파일에 키와 무작위 `credential_revision`을 기록하며 새 키 저장 시 기존 내용을 원자적으로 교체한다. 원문 키를 DB·설정 JSON·작업 snapshot·환경 파일에 중복 저장하지 않는다. 키의 접두어·끝자리·해시를 식별자로 공개하지 않는다.
- 디렉터리 `0700`, 파일 `0600`, 제한된 umask와 파일 소유자를 확인한다. 링크·경로 탈출·잘못된 파일 종류를 거부하고 안전한 디렉터리 핸들/파일 생성으로 경합을 방어한다. 같은 private 디렉터리의 제한된 임시 파일에 쓰고 fsync → atomic replace → 디렉터리 동기화로 공개한다. 기존 파일을 먼저 truncate하거나 삭제하지 않는다.
- 교체 잠금과 예상 revision 검사를 적용한다. 두 설정 탭이 동시에 다른 키를 저장하면 충돌을 알리고 임의로 마지막 요청을 덮어쓰지 않는다. 비정상·빈 입력이나 디스크 오류는 기존 키를 훼손하지 않는다. 성공 후 이전 키 파일·자동 백업·편집기 사본을 만들지 않고 실패/중단 임시 파일을 정리한다.
- 특정 접두어·고정 길이만으로 Gemini 키의 유효성을 확정하지 않는다. 입력 크기·제어문자 등 기본 검사를 하고 실제 인증·모델 접근은 별도의 제한된 연결 검사로 확인한다. 저장 성공과 인증 성공은 다른 상태다. 새 키를 저장해도 전역 AI 선택을 자동 변경하지 않는다.
- 키 삭제는 명시적인 별도 동작과 사이트 확인 모달로 제공한다. 빈 입력을 삭제로 해석하지 않는다. 삭제 후 Gemini는 비활성 상태가 되지만 회의록·선택 기록·다른 AI 인증을 삭제하지 않는다. 로컬 삭제/파일 교체가 Google의 키 폐기나 디스크의 물리적 완전 삭제를 대신한다고 안내하지 않는다.

#### 웹·API·배포

- 설정의 키 입력은 비밀번호형 입력이며 새로 열면 항상 비어 있다. 저장 후 `등록됨`과 연결 상태·갱신 시각만 표시한다. 기존 키 조회/보기/복사 API와 UI는 만들지 않는다. 저장 성공·탭 이탈·로그아웃·소유자 세션 만료 때 입력 메모리를 비우고 실패 응답에도 키를 반사하지 않는다.
- 키 저장/삭제/연결 검사 및 AI 설정 변경은 **소유자 권한 + CSRF/Origin 검증**을 요구한다. 일반 사용자가 직접 API를 호출해도 불가능해야 한다. GET은 비밀 없는 상태만 반환하며 설정 응답은 `no-store`다.
- `SecretStr` 등 입력 표현 보호만 믿지 않는다. FastAPI/Pydantic의 422 검증 오류에 들어가는 `input`, 예외 문자열, 공급자 HTTP 오류·헤더, 로그/진단/테스트 trace도 원문을 누출하지 않도록 별도로 정제한다. URL query·CLI 인자·프롬프트·브라우저 저장소·Vite 변수·HTML 데이터 속성에 키를 넣지 않는다.
- `.gitignore`에 모든 위치의 `.apikey/` 제외를 추가하고 추적 여부를 검사한다. 릴리즈 수집기·백업/복원·진단 묶음·Windows/WSL 동기화는 비밀 디렉터리와 관련 임시 파일을 명시적으로 거부/제외한다. 설정 경로가 변경되거나 private 파일이 공개 디렉터리 아래에 잘못 놓인 경우도 시험한다. 이미 추적된 비밀은 ignore만으로 해결되지 않으므로 원문을 출력하지 않고 소유자에게 폐기/교체가 필요함을 알린다. Git 이력 강제 재작성은 하지 않는다.
- “업로드하지 않음”은 키 파일을 Git·공유·백업·모델 입력 파일로 보내지 않는다는 뜻이다. 최초 입력은 브라우저에서 로컬 서버로 전달되며, Gemini 사용 시 키는 Google HTTPS API의 인증 수단으로만 전달된다. 네트워크 인증 자체가 없는 것처럼 설명하지 않는다. 소스/미디어/다른 공급자에는 전달하지 않는다.
- 파일 권한은 같은 OS 소유자나 root까지 막는 암호화가 아니다. 이 한계를 README에 짧게 명시하고 암호화한 것처럼 표시하지 않는다. 실제 키·CLI 토큰은 개발 세션의 문맥·`.workflow` 증거·스크린샷에도 넣지 않는다.

### M3.3 전역 AI 설정과 선택 가능 상태

설정 화면에 `Gemini API`, `Codex CLI`, `Claude CLI` 세 항목을 항상 표시한다. 내부 ID는 `gemini_api`, `codex_cli`, `claude_cli`로 고정한다. 공급자별 설치·인증·모델 상태와 사용 불가 이유를 보여주고 **하나만 활성 AI로 저장**한다.

| 상태 | 선택 정책 |
|---|---|
| API 키 없음 / CLI 미설치 / 런타임 로그인 없음 | 해당 항목 비활성, 필요한 설정 안내 |
| 잘못된/만료된 인증, 지원하지 않는 CLI 버전·격리 또는 모델 | 비활성, 재인증/설치/설정 안내 |
| 새 키의 연결 확인 전·검사 중 | 선택 보류. 이미 저장한 전역 선택을 다른 AI로 바꾸지 않음 |
| 인증과 해당 기능에 필요한 모델·실행 조건 확인됨 | 선택 가능. 남은 사용량 전체를 보증하는 상태는 아님 |
| 일시적 네트워크 장애·속도 제한·사용량 소진 | 인증 없음과 구분. 기존 선택은 보존하고 생성 가능 여부/재시도 상태를 별도 표시 |

- 설정은 SQLite의 비밀 없는 단일 정책 레코드에 영속 저장한다. 최소 `active_provider`, 공급자별 명시적 모델 설정, `revision`, 갱신 시각을 둔다. 브라우저 localStorage나 서버 시작 시 읽은 환경 변수만 바꾸는 방식은 안 된다. 앱·워커 재시작과 여러 탭에서 일관되어야 한다.
- 공급자를 저장할 때 서버가 enum·권한·최신 준비 상태·예상 설정 revision을 검사한다. 프런트엔드의 disabled만으로 보호하지 않는다. 로그인 만료가 UI 조회 뒤 발생한 경우도 실제 실행 직전에 재검사한다.
- 인증 검사는 **실제 Ubuntu/WSL 워커 사용자와 전용 런타임 환경**에서 한다. Windows 호스트에 로그인돼 있거나 파일 하나가 존재한다는 이유만으로 준비됐다고 간주하지 않는다. 검사 결과에는 원문 키·토큰·계정 이메일을 포함하지 않는다.
- 화면 조회/일반 상태 polling에서 생성 API를 호출하지 않는다. 파일 상태·공식 CLI 로그인 상태·캐시된 모델 정보를 먼저 확인하고, 필요한 원격 검사는 소유자의 명시적 연결 확인에서 짧은 timeout/TTL/예산으로 실행한다. 실제 한도는 알 수 없으면 미상으로 표시한다.
- 기존 설치의 기본 공급자는 `codex_cli`로 이전하고 기존 모델·경로·제한을 유지한다. 인증이 없으면 선택된 Codex를 사용 불가로 표시할 뿐 Gemini/Claude로 자동 전환하지 않는다. 새 설치도 다른 공급자를 몰래 선택하지 않는다.
- 준비된 AI가 없어도 목록·기존 결과·수동 편집·내보내기·로컬 음성 처리까지 막지 않는다. AI 단계는 명확하게 차단하고 설정 연결/취소/전사만 종료로 복구한다. 신규 입력의 AI 생성 옵션을 다시 사용자별로 끄게 만들지 않는다.
- 일반 화면에는 필요한 경우 활성 AI의 표시 이름·생성 가능 여부·설정 필요 여부만 제공한다. 비밀·환경 경로·상세 진단은 소유자 화면에 남긴다. 예전 `allow_external_text=false` 자료는 단순 열람이나 설정 변경만으로 전송하지 않는다.

### M3.4 공통 공급자 경계와 세 어댑터

작은 공통 인터페이스와 공급자 registry/factory를 둔다. 예를 들어 `capabilities`, `check_ready`, `generate_json`, 정제된 `usage/error` 계약을 공유한다. 파일명은 기존 구조에 맞게 정하되 공통 경로가 특정 공급자의 private 구현을 직접 가져오지 않게 한다.

- 현재 `codex_provider.py`의 공통 지침·공통 예외·구조 검증을 공급자 중립 모듈로 분리한다. 실제 전송, 인증, schema 변환, 응답 포맷, 토큰/문맥 제한은 어댑터의 책임이다. 서비스별 분기문을 회의/영상/웹 화면마다 복제하지 않는다.
- 공통 문서 스키마와 원문 ID/시각·한국어·숫자/날짜·논제 검증을 유지한다. 공급자별 JSON Schema 지원 범위가 다르므로 현재 Codex용 `strict_schema()`를 모든 공급자에 그대로 적용하지 않는다. 전송 schema와 정본 검증 schema의 변환을 계약 시험으로 연결한다.
- 실제 모델 ID와 지원 capability를 설정/버전으로 명시한다. Gemini·Claude 모델 이름을 기존 `codex_model`에 넣거나 무조건 같은 reasoning 옵션을 보내지 않는다. 세 공급자 모두 회의/영상/긴 입력에 필요한 구조화 출력을 지원하는 모델을 P0에서 확인한다. 최신 모델이나 무료 한도를 기억만으로 고정하지 않는다.
- 문맥 제한은 공급자별 모델 정보와 보수적 입력·출력 여유로 계산한다. Gemini/Claude가 `codex-home/models_cache.json` 때문에 실패하지 않아야 한다. 원문 전체가 한 번에 안 들어가면 기존 발언 단위 분할/후반 번복 통합을 재사용하며 뒷부분을 버리지 않는다.

#### Gemini API

- 서버에서 공식 **`google-genai`** SDK의 고정 버전을 사용한다. 명시적으로 전달한 키만 사용하고 `GOOGLE_API_KEY`/`GEMINI_API_KEY` 등 외부 환경이나 다른 Google 계정 자격 증명으로 자동 대체하지 않는다. 누락된 선택적 의존성이 앱 전체 또는 Codex를 깨뜨리지 않게 한다.
- 필요한 전사 텍스트·허용된 메타데이터만 텍스트 생성 API로 보낸다. 원본 음성/영상·임베딩·전체 로컬 파일·YouTube 링크를 Gemini Files/영상 분석 API로 보내는 기능은 넣지 않는다. 외부 검색·도구 실행도 사용하지 않는다.
- 공식 API endpoint와 TLS 검증을 사용하고 사용자 입력 endpoint나 인증 헤더를 유지한 임의 리디렉션을 허용하지 않는다. 키가 URL·debug 로그에 남지 않는 인증 경로를 사용한다. SDK의 암묵적 retry/timeout도 앱의 유한 예산에 맞춘다.
- 구조화 JSON을 공통 문서로 검증한다. 인증/권한 오류, 모델 접근 불가, 429, 서버 오류, 안전 차단, 빈 응답, 출력 길이 초과를 구분하며 불완전 응답을 정상 요약으로 저장하지 않는다.
- 무료/유료 여부는 키 모양으로 알 수 없다. 설정에서 적용 서비스의 비용·데이터 처리 조건을 확인할 수 있게 하고 사용자 허가 없이 결제를 활성화하지 않는다. 무료 Gemini의 기밀/민감정보 제한을 안내하며 실제 시험에는 허가된 공개 또는 가상 전사만 쓴다. 설정 단계의 고지를 사용하고 업로드별 동의 체크박스를 다시 도입하지 않는다.

#### Codex CLI

기존 구독 전용 `CodexCliProvider`의 전용 HOME·CODEX_HOME·stdin 입력·JSON 출력·도구 차단·버전/격리 검사·일회성 실행을 보존해 공통 인터페이스에 연결한다. 현재 검증된 `0.157.1`을 공급자 확장만을 이유로 강제 업그레이드하지 않는다. API 키 기반 유료 호출이나 개발 세션 인증을 대신 사용하지 않는다.

#### Claude CLI

- **공식 Claude Code CLI의 비대화형 `claude -p`**를 사용한다. 로컬 소유자가 해당 CLI의 지원 로그인 절차로 인증한다. OAuth 토큰을 추출해 별도 Anthropic API 클라이언트에 재사용하거나 개인 개발 세션의 인증 파일을 복제하지 않는다.
- 전용 Linux 런타임 HOME과 `CLAUDE_CONFIG_DIR`를 준비하고 설치·로그인·상태 검사·실행이 모두 같은 환경을 사용하게 한다. Windows 로그인 상태를 WSL 로그인으로 간주하지 않는다. Claude가 없어도 나머지 공급자와 앱은 사용 가능하다.
- 공식 문서상 `--bare`는 구독 OAuth 인증을 읽지 않는 모드이므로 구독 CLI 실행에 무조건 붙이지 않는다. 대신 선택한 CLI 버전의 실제 지원 옵션으로 도구/MCP/hooks/플러그인/스킬/브라우저/개발 지침 상속을 차단하고 검증한다. 빈 작업 디렉터리·제한된 환경만으로 충분하다고 가정하지 않으며 격리를 증명할 수 없으면 해당 공급자를 비활성화한다.
- `ANTHROPIC_API_KEY`, 다른 클라우드 공급자/endpoint 설정 등이 비대화형 인증을 바꾸지 않게 환경을 정제한다. 별도 유료 API로의 폴백이나 `--dangerously-skip-permissions`를 해결책으로 사용하지 않는다.
- 전사와 프롬프트는 stdin으로 전달하고 지원되는 JSON 출력/JSON Schema 옵션을 사용한다. CLI의 결과 envelope에서 오류·완료 상태와 `structured_output`을 확인한 뒤 공통 로컬 검증을 한다. 종료 코드 0 또는 단순 자연어 응답만으로 성공 처리하지 않는다.
- 호출마다 새 실행을 사용하고 가능한 세션 비보존 옵션을 버전별로 검증한다. CLI가 남기는 전사 포함 세션/임시 파일도 기존 보관 정책과 삭제 범위에 포함한다. 프로세스 트리 취소·stdout/stderr 크기·시간 제한·내부 turn/retry 제한을 검증한다. 설치/로그인/진단 스크립트와 릴리즈 고지를 추가하되 실제 계정 로그인은 소유자가 한다.

### M3.5 모든 AI 기능의 적용 범위

| 경로 | 전역 AI 설정 적용 |
|---|---|
| 회의 파일의 최초 회의록 생성 | 새 분석 요청에 고정한 공급자 사용 |
| 파일 및 YouTube 영상의 최초 요약 | 같은 공통 생성 경로 사용. YouTube 획득 자체는 기존 로컬 처리 |
| 회의록 초안 재생성·영상 요약 재생성 | 요청 당시 활성 AI로 새 snapshot 생성. 기존 결과/편집본 보존 |
| 제목 없는 파일의 AI 제목 | 해당 문서를 만드는 동일 응답에서 생성. 별도 Codex 호출 금지 |
| 긴 입력의 후보 추출·여러 청크·최종 통합 | 한 작업의 동일 공급자/모델/프롬프트 snapshot 사용 |
| JSON 구조 보정·네트워크 재시도 | 동일 공급자와 영속 예산 사용. 다른 AI로 자동 폴백 금지 |
| 명시적 연결 생성 시험·사용량 진단 | 선택한 검사 대상 어댑터 사용, 제품 생성과 분리된 예산/표시 |

STT/정렬/화자 임베딩, 시각 계산, 사용자 본문 편집, 검색, 내보내기에는 새 외부 AI 호출을 만들지 않는다. 새 AI 기능을 추가할 때도 공통 실행 경계 외부의 직접 호출은 계약 테스트와 코드 점검 대상이다. 제품 설정이 개발용 Astra/Sol 세션의 모델을 바꾸지는 않는다.

### M3.6 설정 변경·대기열·키 교체·캐시

**전역 선택은 새 요청부터 적용하며, 등록된 작업의 공급자를 실행 도중 바꾸지 않는다.** 이는 과거/대기 중 전사 내용이 설정 변경만으로 다른 회사에 전송되는 것을 방지한다.

1. 파일은 업로드가 완료되어 분석 작업을 등록할 때, YouTube는 URL 작업 등록 때, 재생성은 요청 등록 때 **비밀 없는 `GenerationConfigSnapshot`**을 같은 DB 트랜잭션으로 고정한다. 최소 공급자 ID·명시적 모델·설정 revision·프롬프트/schema/어댑터 버전·문맥/출력/호출 한도를 담는다. AI 단계가 시작될 때마다 전역 설정을 다시 읽어 공급자를 바꾸지 않는다.
2. 동일 idempotency key의 응답 유실 재요청은 원래 작업과 snapshot을 반환한다. 그 사이 설정이 바뀌어도 두 번째 작업이나 다른 공급자 요청을 생성하지 않는다. 대기/실행/차단 작업의 일반 재시도도 원래 공급자를 유지한다. 현재 AI를 적용하려면 명시적으로 새 생성 요청을 만들어 저장된 전사를 재사용한다.
3. 키·CLI 토큰은 snapshot에 넣지 않는다. 공급자의 실제 자격 증명은 시도 시작 시 전용 저장소에서 읽는다. 아직 시작하지 않은 Gemini 작업은 교체된 새 키를 사용한다. 이미 외부 전송 중인 호출은 이전 키로 끝날 수 있음을 구분한다. 긴 작업의 호출 사이 키 교체/삭제가 확인되면 `AI_CREDENTIALS_CHANGED` 등으로 멈추고 명시적 재시도를 받으며, 옛 키를 디스크에 보관하거나 서로 다른 키로 조용히 계속하지 않는다.
4. 설정 변경은 소유자 설정/상태 캐시를 무효화하고 프로세스 간에 반영한다. API 서버나 워커가 시작 시 생성한 `Settings` 객체만 참조해 새 선택을 무시하지 않게 한다. 관련 없는 보관 설정 revision 변화가 진행 중 생성 설정을 깨뜨리지 않도록 별도 revision을 둔다.
5. 생성 identity와 전체/청크 checkpoint는 공급자·모델·공통/공급자 프롬프트·schema·어댑터 버전·입력 snapshot·실행 옵션을 포함한다. 같은 전사를 Gemini로 요청했는데 Codex의 중간 결과/완성본을 그 응답처럼 반환하지 않는다. 키 원문·키 해시는 생성 identity에 넣지 않는다. 무작위 credential revision은 키 교체 감지용일 뿐 키 자체를 추정할 자료가 아니다.
6. 결과와 usage에 실제 호출 공급자·설정 모델·확인 가능한 실제 모델·생성 설정 revision을 서버가 기록한다. LLM에게 자기 공급자를 쓰게 하지 않는다. 공급자가 실제 모델 정보를 주지 않으면 추정해 채우지 않는다. 과거 결과는 호환 필드/미상 상태로 읽고 현재 선택으로 출처를 덮어쓰지 않는다.
7. 기존 미완료 작업은 당시 Codex 설정을 복구 가능한 범위에서 고정한다. 마이그레이션 뒤 갑자기 Gemini/Claude로 보내거나 예산을 0부터 다시 만들지 않는다. 복구 불가능하면 명확한 설정 확인 상태로 두고 저장된 전사로 새 생성을 안내한다. 기존 완료 문서·수동 수정·선택 버전·재생성 중 편집 충돌 계약은 유지한다.
8. 분석/AI 재생성 **두 lane은 유지**한다. 같은 공급자의 네트워크 호출과 CLI 인증 갱신은 초기에는 공급자별 동시 1개로 제한하는 공통 프로세스 간 잠금/lease를 사용한다. 이 제한은 ASR을 직렬로 되돌리는 것이 아니다. 다른 공급자의 기존/신규 작업은 각 lane 안에서 진행할 수 있다. 대기는 취소 가능하며 네트워크 중 DB 쓰기 트랜잭션을 잡지 않는다. 재시작·프로세스 사망 후 잠금 복구를 검사한다.
9. 공통 오류는 인증 필요/인증 무효/모델 불가/격리 불가/속도·사용량 제한/네트워크/불완전 출력/예산 소진으로 구분한다. 인증 오류를 무한 retry하지 않는다. 429의 대기 안내와 유한 backoff를 적용하고 키 교체가 프로젝트 쿼터를 초기화한다고 간주하지 않는다. SDK·CLI 내부 retry까지 포함해 무제한 호출이 생기지 않게 한다.
10. 외부 호출 전 영속 예약, 결과 저장 전 attempt·취소·삭제 검사, 자식 종료 확인을 유지한다. timeout/cancel 뒤 외부 처리가 이미 진행됐을 수 있으므로 정확히 한 번 과금이나 취소 시 사용량 환불을 보장하지 않는다. 키·공급자 변경과 재시작으로 이미 소비한 작업 예산을 초기화하지 않는다. 앱 관측 사용량과 전체 계정의 잔여량은 별개로 표시한다.

### M3.7 API·화면·운영 인수 범위

API 경로는 아래 형태를 기준으로 기존 구조에 맞게 구현한다. 설정과 키의 변경 revision은 구분하며 반환값에 비밀 필드는 존재하지 않아야 한다.

| API 예시 | 권한·역할 |
|---|---|
| `GET /api/settings/ai` | 소유자. 선택 공급자, 비밀 없는 설정·준비 상태·revision |
| `PATCH /api/settings/ai` | 소유자+CSRF. 사용 가능한 공급자 선택 및 모델 설정 저장, 낙관적 충돌 검사 |
| `PUT /api/settings/ai/gemini-key` | 소유자+CSRF. 새 키 한 번 수신, 안전한 파일 교체, 상태만 반환 |
| `DELETE /api/settings/ai/gemini-key` | 소유자+CSRF. 명시적 삭제, 상태 무효화 |
| `POST /api/settings/ai/{provider}/check` | 소유자+CSRF. 제한된 연결 검사, 생성 시험은 별도 명시적 요청/예산 |
| 일반 화면용 최소 AI 상태 | local session. 활성 표시 이름·사용 가능 여부만 제공하고 민감 진단은 제외 |

설정 화면은 `AI 연결 및 선택 → 자료 보관 → 진단` 순서다. 저장 중 중복 제출·다른 탭 충돌·세션 만료·입력 지우기·선택 불가 이유를 처리한다. 기존 헤더 로그아웃과 사이트 모달, 일반 기능의 키 없는 사용을 유지한다. 모델별 고급 튜닝 UI나 프롬프트 편집기를 새 제품 기능으로 확장하지 않는다.

Ubuntu 설치/doctor는 공급자별 선택적 준비 상태를 보여준다. Claude/Gemini가 미설정이라고 앱 전체 설치 실패로 만들지 않는다. Python·CLI 버전을 잠그고 라이선스 고지를 갱신하되 기존 ML 의존성을 불필요하게 업그레이드하지 않는다. systemd/WSL에서도 같은 config/credential 경로를 사용하고 소스 동기화에 비밀을 포함하지 않는다. 백업 복원은 공급자 설정을 복원할 수 있지만 `인증 준비됨` 캐시는 복원하지 않으며 새 환경에서 재검사한다.

#### 실제 실행과 과잉 검증 방지

- 마스터는 단계별 최소 영향 검사 후 커밋을 고정한다. 검증 위임은 **M3-A: 비밀 저장·설정 API·마이그레이션·제외 정책**, **M3-B: 세 어댑터·모든 호출 경로·작업 전환·웹·운영**의 두 묶음으로 한다. 기존 workflow의 queue·예산·불변 결과·알림 소비 규칙을 그대로 사용한다.
- 기본 회귀는 fake adapter, 가짜 키, 저장된 전사·schema fixture와 mock CLI/HTTP로 한다. 실제 STT/pyannote나 YouTube를 다시 실행해 공급자 선택을 시험하지 않는다. 관련 변경이 없는 M2 모델/획득 증거는 유효 지문을 확인해 재사용한다. 120분 soak는 실행하지 않는다.
- 실제 공급자 확인은 권한과 예산이 확보된 공급자별로 **짧은 가상/공개 전사의 회의록 1회·영상 요약 1회**를 기본으로 잡고 호출/시간/토큰 상한을 별도 기록한다. 승인된 최소 인증/모델 검사와 생성 검사를 구분한다. 구조/취소/오류 조합은 mock으로 검증하며 정상 결과를 얻을 때까지 무제한 실제 호출하지 않는다.
- 새 Gemini 과금, 외부 전송, Claude 설치/로그인 권한이 필요하면 실행 전에 소유자에게 필요한 항목만 묻는다. 키는 앱 설정, 로그인은 공식 CLI에서 소유자가 수행하게 하며 채팅으로 비밀을 요구하지 않는다. 개발 세션의 인증을 가져와 차단을 우회하지 않는다.
- 인증이 없는 공급자는 구현·mock 계약 검증과 실제 실행 상태를 분리해 `LIVE_BLOCKED` 사유를 남긴다. 해당 어댑터를 완전히 검증했다고 쓰거나 UI에서 준비됨으로 만들지 않는다. 나머지 독립 구현을 진행하고 정확한 재개 지점을 남긴다.
- 최종 저비용 전체 회귀는 마스터/검증자 중 한쪽에서 한 번 실행하고 증거를 공유한다. 수정 후에는 실패 항목과 영향 범위만 재검증한다. M3 증거 프로필을 추가할 때 기존 M2의 모든 고비용 실행을 새 필수 조건으로 복제하거나 누락된 `.workflow`를 과거 PASS로 채우지 않는다.

### M3.9 완료·인수인계 및 공식 참고

완료 시 활성 AI 설정·키 입력/교체/삭제·비활성 이유·공급자별 설치/로그인·설정 적용 시점·비밀 제외 범위를 README에 반영한다. 앱은 로컬 개인 사용이며 웹 소유자 키와 외부 AI 인증은 별개임을 유지한다. 공급자별 실제 실행 여부·검증 커밋·미해결 차단·다음 행동은 `.workflow`에 기록한다. 기존 완료 기록을 삭제하지 않고 M3 상태와 실제 구현 계약을 갱신한다. 프로젝트 본문은 한글, 커밋 메시지는 영문, 소스·문서는 LF를 사용한다. 키/토큰이 없는 문서·코드만 원격에 반영한다.

아래 공식 문서를 기준으로 **구현 시 실제 설치 버전·계정에서 다시 확인**한다. 구조화 출력은 의미 정확도 보증이 아니며, SDK/CLI 인증 성공도 무제한 사용량을 보증하지 않는다.

- [Gemini API 키와 서버 측 보관](https://ai.google.dev/gemini-api/docs/api-key), [공식 Python Gen AI SDK](https://googleapis.github.io/python-genai/), [Gemini 구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output).
- [Gemini 서비스 조건](https://ai.google.dev/gemini-api/terms), [프로젝트별 속도·사용량 제한](https://ai.google.dev/gemini-api/docs/rate-limits). 무료 서비스의 민감/기밀정보 제한과 결제 상태별 조건을 구분하고 API 키 교체로 쿼터를 우회하지 않는다.
- [Codex 비대화형 실행](https://developers.openai.com/codex/noninteractive/), [Codex 인증](https://developers.openai.com/codex/auth/). 기존 구독 전용 어댑터의 실행 계약을 보존한다.
- [Claude Code 비대화형 실행](https://code.claude.com/docs/en/headless), [Claude Code 인증](https://code.claude.com/docs/en/authentication). 구독 인증과 `--bare`의 차이, 환경변수 인증 우선순위, JSON 출력과 실행 격리를 확인한다.
